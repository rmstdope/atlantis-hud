ah-1mpx.2 — round 5: the states the happy path hides

Rounds 1–4 settled what an Army is, where it lives, and every word of the busy case. This round is only about ah-1mpx.2 — the source rail itself — and only about the moments the earlier mockups did not draw: while the Armies are still coming out of storage, when a save fails, when an Army has nothing in it yet, and what the Rename / Delete strip looks like before there is anything to export.

Two of these exist only because this bead ships before its siblings. Export arrives in ah-1mpx.3 and dragging in ah-1mpx.4 — so a control and a sentence that both assume them have to say something honest in the meantime, and then either change or not.

S1 — the rail while the Armies are still loading

Armies come out of SQLite or IndexedDB after the pane has already painted. On a fast machine this is one frame; on a cold web start with a large database it is visible. The rail must say something in between.

S2 — the strip above the table, before there is an export

Rounds 3 and 4 drew it as Rename · Delete · Export…. Export is built in the next bead. So for one bead's worth of time this strip either carries a control that does nothing, or it is one control shorter and grows later.

Option A — Export… is there, and disabled
Northern Host RenameDelete Export…
  • The strip is its final shape from the first day; nothing moves under the navigator's hand when the next bead lands.
  • A dead control. Every dead control is a small promise that the application is broken, and there is no honest tooltip that is not an apology for the backlog.
Option B — two buttons now, three next bead recommended
Northern Host RenameDelete
  • Everything on screen works. Nothing has to be explained away.
  • The strip is already a row of buttons, so a third arriving is not a redesign — it is one more button on the end.
  • The strip changes shape between two releases, which somebody watching closely will notice.

S3 — an Army with nothing in it, before dragging exists

P3 quoted this as “Drag units here from any list, or use Add to army on a unit.” — but dragging is ah-1mpx.4. In this bead the only way in is the right-click menu. The line either tells the truth now and is rewritten later, or is written once to be true in both.

Option A — true now, rewritten in .4
Northern Host has no units yet. Right-click any unit and choose Add to army.
  • Names the one gesture that actually works today, and names it exactly.
  • A string that is scheduled to change one bead later, which means a smoke test that is scheduled to change with it.
Option B — written once, true in both recommended
Northern Host has no units yet. Add units to it with Add to army, on any unit in any list.
  • Never wrong, never rewritten. Dragging arrives later as a shortcut for something the line already told you was possible.
  • “in any list” is the part that matters: it says an Army is not tied to the hex on screen.
  • Says nothing about dragging even after dragging is the nicer gesture.
Option C — just the fact
Northern Host has no units yet.
  • Nothing to keep true. The shortest thing that can be said.
  • An empty state that does not say how to leave it is the one place the application had the navigator's full attention and said nothing.

S4 — when the save fails

Every change to an Army is optimistic: the rail moves at once and storage catches up. When the write fails the store rolls the change back, so the Army silently returns to what it was — a renamed Army un-renames itself, an added unit vanishes from the count. The question is whether anything says so.

Bulk removal — Option A: it just happens recommended
2 units were not in this turn's report. Remove them
  • The two rows are on screen, named, and sorted where you can see them; you are looking at exactly what you are about to remove.
  • Removing a unit from an Army destroys nothing — the unit is untouched, and it can be added back from any list.
  • No way back if it was a slip, since there is no undo.
Bulk removal — Option B: it asks
Remove 2 units from Northern Host? They were not in this turn's report. The units themselves are not affected.
CancelRemove
  • Matches the delete-an-Army confirmation already agreed, so the two destructive-looking actions behave alike.
  • A dialog for something reversible by hand in two clicks, on a bar you must pass every turn until you deal with it.
Everything else in ah-1mpx.2 is already decided — the rail, the Seen and Hex columns, inline naming, the delete confirmation and every string in the busy case are quoted in docs/ui/ah-1mpx-r3.html and recorded in the epic's design. Once these five are answered the plan can be written with nothing left for the implementer to choose.
