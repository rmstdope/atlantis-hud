ah-97ij — a skill that looks the Atlantis rules up

The problem. Every role here reasons about Atlantis constantly and answers from recall. docs/order-checks/README.md:41 admits it outright about the STUDY rules: “Source: the rules text at atlantis-pbem.com/rules, unread for this investigation.” Bead ah-9js cost an implementation, a ruleset regeneration and a round of test edits because a plan and its expected result disagreed about what the data page calls a building — and the data page, the arbiter, was never opened.

What I found. Both pages are plain server-rendered HTML, no JavaScript. The rules page carries 129 named anchors — one per section, per table and per order — so it slices exactly. The data page is one <pre> block of 711 entries (480 skill levels, 171 items, 60 objects), median 105 characters each. And this repository already commits both pages verbatim as tests/fixtures/ruleset/neworigins-rules.html and -data.html — which I checked byte-for-byte against the live site just now: identical today.

question 1Where the skill reads from

AThe committed copyrecommended

The skill reads tests/fixtures/ruleset/*.html, already in the repo. A refresh command re-fetches them when you ask.

  • Instant, offline, works at 2am with no network.
  • Deterministic — the same question gives the same answer twice.
  • A rules change arrives as a reviewable diff in a PR.
  • It is what docs/ruleset-contract.md already decided for ruleset.json.
  • Goes stale silently unless something refreshes it — question 2.

BLive fetch every time

The skill fetches the page on every lookup and slices the response.

  • Never stale.
  • 284 KB per lookup, and WebFetch summarises — the agent gets a paraphrase, not the rule.
  • A network dependency inside an unattended implementer.
  • No diff, so nobody ever learns the rules changed.

CLive, falling back to the copy

Try the network; use the committed copy when it fails.

  • Current when it can be.
  • Two code paths, and the agent cannot tell which answer it got.
  • The same summariser loss as B on the good path.

question 2How anyone notices the game changed

The rules page says Last Change: Jun 20, 2025 and opens with “Changes from New Origins v7: Meals are now 50 silver each (was 30 silver).” That is exactly the kind of number this application prices things with. The committed copy is current today; nothing guarantees it stays so.

AA scheduled job opens a PRrecommended

A weekly GitHub Action re-fetches both pages and opens a PR when they differ.

  • Rules drift becomes a reviewed diff nobody has to remember to look for.
  • Never blocks unrelated work.
  • One more workflow to own.

BA CI check that fails

CI re-fetches on every run and fails the build when the pages differ.

  • Impossible to ignore.
  • Blocks every unrelated PR the day the site is edited.
  • Puts the network on the critical path of every build.

CNothing automated

Every lookup prints the snapshot date; refreshing is manual.

  • No new machinery at all.
  • In practice nobody refreshes until something is already wrong.

question 3What the skill covers

ah-9js failed in the gap between what the game says and what this repository believes. The repo derives config/public/ruleset.json from these same two pages (171 items, 96 skills, 58 buildings) and the app shows it in the game-data dictionary.

AThe sources, and the repo's own copyrecommended

Lookups over the two pages, plus a short section naming config/public/ruleset.json, saying which side is the arbiter, and giving the command to check one against the other.

  • Addresses the recorded failure directly rather than its neighbourhood.
  • An agent that finds a disagreement knows which side is wrong.
  • A longer skill, and one more thing to keep true.

BThe two sources only

Lookups, and nothing else.

  • Shorter; one job, done once.
  • Leaves the exact gap ah-9js fell into.

question 4Where agents are told to reach for it

A constraint worth knowing before you answer: every skill and agent file here except .claude/skills/release/ is a symlink into the cerebro submodule, which is game-agnostic and shared with other projects. So the instruction cannot go into plan-bead, implement-bead or any role definition — that would put Atlantis knowledge into shared code, which is the one thing the bead rules out. It has to live in this repository's own files.
