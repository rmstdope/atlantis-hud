Round 2 — the mark that says part of the month could not be counted

You chose Q2 option C: count every order that can be counted, and let the cell admit that one could not. This page settles what that mark is, and solves a problem C has that the mockup did not show.

The problem. The ITEMS cell is a single line with overflow:hidden; text-overflow:ellipsis and a default width of about 220px. A mark placed after the list is the first thing lost to truncation — and a long item list is exactly when a player most needs to know something is missing. Every stage below is drawn at the real column width, with a unit that genuinely overflows it.

unit 5530
  sell 40 FUR
  buy all HORS    ; cannot be counted
  give 5512 2 HERB

M1 — the mark trails the list

What the Q2 mockup drew. Fine on a short list; gone on a long one.

IDNAMEITEMS
*5530Traders1580 SILV, 4 HERB + ?
*5531Caravan1580 SILV, 4 HERB, 12 LEAT, 3 SWOR, 40 WOOD, 2 HORS + ?
  • Reads naturally on the short row: the list, then a note that there is more.
  • The second row has the identical problem and shows no mark at all. The truncation ate it, and nothing distinguishes that row from one whose month is fully counted.
  • Whether the warning is visible depends on how wide the player dragged the column.

M2 — the mark leads the list

Placed first, so it can never be truncated away.

IDNAMEITEMS
*5530Traders? 1580 SILV, 4 HERB
*5531Caravan? 1580 SILV, 4 HERB, 12 LEAT, 3 SWOR, 40 WOOD, 2 HORS
  • Always visible, at any column width. Marked rows line up down the left edge and can be scanned at a glance.
  • A leading ? reads as though the first item is in doubt, when the doubt is about the whole month.
  • It shifts the numbers right by a character, so the column no longer aligns with unmarked rows.

M3 — the mark is pinned to the right edge and the list truncates before it

The cell reserves the mark its own space; the item list truncates inside what is left. Trailing, as M1, but it cannot be eaten.

IDNAMEITEMS
*5530Traders1580 SILV, 4 HERB?
*5531Caravan1580 SILV, 4 HERB, 12 LEAT, 3 SWOR, 40 WOOD, 2 HORS?
  • Visible at every width, on both rows, without disturbing the left alignment of the numbers.
  • Trails the list, which is where a "and there is more" note belongs.
  • Uses the same ? the Silver column already shows for a figure it will not guess at, so the vocabulary is one the player has met.
  • The cell becomes a two-part flex layout instead of one truncating span — slightly more markup on the hottest row in the table.
  • Unmarked rows keep the full width: nothing is reserved on a row with no doubt.

The state the happy path hides — a unit whose only order cannot be counted

unit 5540 / buy all HORS and nothing else. Today this row is not italic and not in the preview at all, because no field changed. Two readings, drawn with M3's mark:

Nothing is projected, so nothing is italic — but the mark says the month was not empty.

  • Italic keeps its exact meaning: this figure is a projection. Nothing here is.
  • The row is still distinguishable from a unit with no orders at all.

S2Left exactly as it is today

No mark, no italic. The row says the report's truth and nothing else.

IDNAMEITEMS
*5540Scouts20 SILV, 6 HERB
  • Nothing new to build for this case.
  • A player who wrote buy all HORS sees a row that looks like they wrote nothing.

The hover, in both wordings

The cell's tooltip today is one line: was: <the report's items>. With a mark there is a second thing to say.

W1Names the order

hoverwas: 300 SILV, 40 FUR, 6 HERB
and more that cannot be counted: buy all HORS
  • The player can see exactly which line to look at.
  • Two uncountable orders make it two lines; four make it four.

W2Names the rule

hoverwas: 300 SILV, 40 FUR, 6 HERB
One of this unit's orders moves goods that cannot be counted yet.
  • One line however many orders are in doubt.
  • Leaves the player to find which order it meant.
