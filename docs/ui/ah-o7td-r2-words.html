ah-o7td — round 2: the words, and the awkward cases

Settled last round: Option B (everything spends_the_month counts, so MOVE/SAIL/ADVANCE, TAX and PILLAGE are in, CAST is out); the second and later lines are marked, the first left alone; a toggle in the Warnings tab, on by default.

What I found since: the same finding is shown in three places, and only one of them counts lines the way the core does. orderEditor.ts:145 says it outright — “line 604” means nothing to someone looking at a four-line block. The finding’s position is re-based per unit, but a line number written inside the message text is not. So W1 below is correct in the map-wide Problems list and wrong in the unit’s own panel.

W1 naming the line

unit 5187 MOVE N NE STUDY Combat a second order for the month: line 2 already gives this unit MOVE, and only one of the two will run

Same shape as form-alias-reused. In the whole-document Problems list, “line 2” is right. In the Orders panel, where this block is re-based to start at line 1, it is wrong — and in a real orders file the number would be something like 604.

W2 naming the order instead of the line

unit 5187 MOVE N NE STUDY Combat MOVE already spends this unit's month, so this STUDY will not run

No line number, so it reads correctly in all three places. Names both orders, so the player can see which one is being kept and which dropped without looking anywhere else.

W3 shorter, no claim about which one wins

unit 5187 MOVE N NE STUDY Combat this unit already has a month-long order: MOVE

Says only what is certain. Does not promise that MOVE is the one that runs — which the rules never state, and which the sequence of events makes plausible but not sure.

Three orders how each wording repeats

unit 5187 MOVE N BUILD Tower MOVE already spends this unit's month, so this BUILD will not run ENTERTAIN MOVE already spends this unit's month, so this ENTERTAIN will not run

Both later lines point back at the same first order, not at each other. W3 would read this unit already has a month-long order: MOVE twice, identically.

Case 1 MOVE and SAIL in the same block

unit 5187 MOVE N SAIL NW

rules/move says multiple MOVE orders chain, and rules/sail shows SAIL N / SAIL NW as a form of one route. Neither says anything about mixing them. They are separate variants in the core (Intent::Move and Intent::Sail), so this is a decision, not a fact: walking and sailing in one month, or a conflict worth marking?

Case 2 two STUDY lines

unit 5187 STUDY Combat STUDY Longbow STUDY already spends this unit's month, so this STUDY will not run

Nothing in the rules lets two STUDY orders chain the way MOVE and TEACH do, so this warns — but the message names the same word twice, which reads oddly. Same for two PRODUCE lines, two BUILD lines, two WORK lines.

Case 3 a block with a line the reader could not parse

unit 5187 MOVE N STUDY Combat MOVE already spends this unit's month, so this STUDY will not run ASSASSINATE 4021

The Units that do nothing check refuses to judge a unit holding an order it could not read — an unreadable line may well be a month’s work, so claiming the unit does nothing could be wrong. This check is the other way round: two readable month-long orders are two whatever else the block holds, and an unread line can only add a third. So it still warns. That is my call unless you disagree.

Case 4 a unit formed this month

unit 5187 FORM 2 new 2 WORK STUDY Combat WORK already spends this unit's month, so this STUDY will not run END

Handled for free by the existing machinery — the finding carries the formed subject, and the Problems list shows it as new 2 with a click through to 5187. Nothing to decide, shown so you can see it.

The settings entry as it would read in the Warnings tab

ORDERS Two orders for one month A unit given more than one order that spends its month, such as MOVE and STUDY together, where only one of them will run.

It would sit in the existing Orders group, beside Units that do nothing — the two are opposite halves of the same idea.
