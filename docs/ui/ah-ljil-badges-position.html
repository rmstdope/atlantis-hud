§3  What the move must not break three things the code comments warn about, all measured

1. Zoom-to-fit reads the strip's own box. data-map-overlay="top" (AppShell.tsx:3104) tells the map which edge is covered, so frameAll frames the world into the part you can actually see. BadgeMenu.tsx:20 warns that a panel which grew that box would make zoom-to-fit fit the map into a smaller one. Moving the chip from centre to right changes what that element measures, so zoom-to-fit has to be checked, not assumed.
2. The open menu has to clear the panels, and only while open. The strip is z-20 and lifts to z-30 only when something is expanded. AppShell.tsx:3095 records what happened without it (ah-v09e): “the Badges menu's lower rows landed on the units dock's title bar and stopped taking clicks.” The comment is equally clear about why it is conditional: lifting it always “swallows clicks meant for whatever sits under it — twelve smoke tests' worth”. The zoom cluster has none of this. Moving the chip into it without carrying the z-handling reintroduces exactly that bug.
3. Only the top 48px of the map takes clicks. MapCanvas.tsx:1527: the inspector panels cover the rest with a full-bleed overlay that clears only the first forty-eight pixels, so “controls anywhere else are unreachable however visible they look”. Both controls are inside that band today and must stay inside it.
