Order OCD — the cases the happy path hides

Settled already: indentation applies both as you type and on the whole block when the tidy runs; END and ENDTURN line up with their openers; trailing blank lines collapse to exactly one newline when the tidy runs, not while you type. What is left is what happens when the orders are not well formed, and what the setting now calls itself.

1 · A block that is not closed, or closed by the wrong keyword

Half-written orders are the ordinary state of a turn. FORM 1 with no END yet, or a stray END closing nothing, and the re-indent has to decide what to do.

AIndent by the running depth anyway

The walk counts what it sees. An unclosed FORM means everything after it stays one level in, to the bottom of the block; a stray closer that matches nothing changes nothing.
TURN
 NAME UNIT "Scout"
 FORM 1        ← never closed
  STUDY COMBAT
  WORK
  MOVE N
  ENDTURN   ← stray: FORM is innermost
  • The runaway indent is itself the signal that a block was left open
  • One rule, no special cases to explain or test
  • One missing END visibly shifts every line below it
  • The stray ENDTURN ends up indented, next to nothing

BLeave a broken block alone

If the walk finds an unclosed block or a stray closer anywhere in the unit, the whole-block re-indent does not run at all. Case tidying and the trailing newline still do, and Enter still indents as you type.
TURN
NAME UNIT "Scout"
FORM 1        ← never closed
STUDY COMBAT
WORK
MOVE N
ENDTURN
(left exactly as typed until
 the block parses)
  • Never rearranges text whose structure it cannot actually read
  • The moment you type the missing END, it all snaps into place
  • "Why is nothing indented?" has an answer you cannot see on screen
  • A unit with one old stray closer never gets tidied at all

2 · Blank lines, and the player's own comments

A block is rarely only orders. ; lines are the player's notes, @; is a repeating comment the server acts on, and blank lines are thinking room.

iComments indent, blanks stay empty

A comment is a line of the block like any other. A blank line is left truly empty — no invisible spaces on it.
TURN
 ; scouting party
 NAME UNIT "Scout"

 @; keep working
 MOVE N
ENDTURN
  • A note lines up with the orders it is a note about
  • Nothing invisible is ever written into the file

iiComments indent, blanks get the indent too

Every line inside a block carries the block's indentation, including the empty ones — so the caret starts in the right column when you click one.
TURN
 ; scouting party
 NAME UNIT "Scout"
 
 @; keep working
 MOVE N
ENDTURN
  • Clicking a blank line puts you where the next order goes
  • Trailing whitespace on otherwise empty lines, written to the orders file

iiiComments stay at column 0

Only real orders are indented; anything the server will not act on is left hard against the left edge.
TURN
; scouting party
 NAME UNIT "Scout"

 @; keep working
 MOVE N
ENDTURN
  • Notes read as a margin, distinct from the orders
  • @; is an order, so the rule would have to split the two
  • Breaks up the indented run the eye is following

3 · A unit with no orders at all

"Exactly one newline at the end" — of nothing. Clicking in an empty editor is exactly the case the ask came from, but a blank line written into an empty draft is a line the player never opened.

iEmpty stays empty

A unit with no orders shows an empty editor. The caret is already on line one, so there is nothing the newline would buy.

(nothing typed yet)
  • Clicking anywhere lands on line one regardless — the symptom cannot occur
  • No unit gains stored orders merely by being looked at

iiAlways one newline, even when empty

The rule holds literally: every block ends with a newline, so an empty one is a single blank line.

(one blank line above)
  • One sentence describes every unit with no exceptions
  • Opening a unit dirties its draft, so it saves and appears edited

4 · What the setting calls itself

Today it says one thing and will now do three. This is the line in Settings → Order OCD.

W1All three, plainly

Order OCD

Uppercase the command keywords as you write, indent each level of a nested FORM or TURN by one space, and end every unit's orders with a single blank line. Text inside quotes is left alone.

  • Says everything it does, so nothing it does is a surprise
  • Three clauses in one sentence, and the longest description in the dialog

W2The intent, then the detail

Order OCD

Keeps your orders tidy as you write: keywords uppercased so MOVE, STUDY and ALL stand out from names, one space of indentation per level inside FORM and TURN, and a clean line at the end. Text inside quotes is left alone.

  • Leads with why you would want it rather than with a list
  • "a clean line at the end" is vaguer than the thing it does
