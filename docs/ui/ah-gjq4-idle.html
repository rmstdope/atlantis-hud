ah-gjq4 — an idle unit works, and earns

A unit with no month-long order automatically WORKs, and work pays the region's wage. The forecast prices only an explicit Intent::Work, so an idle unit shows no income — while its upkeep is still charged. It can be shown short of money, or starving, when the wages it will really earn would have paid.

That is the same false-alarm class as ah-fjty, ah-eacd, ah-e66j and ah-tdsi — all four warned about a unit something was going to pay for. An idle unit is probably the commonest unit in a real turn, so this is the widest of them.

The definition of “no month-long order” is already shipped and exhaustive: spends_the_month (semantics.rs:714), written as a full match precisely so a new order cannot slip through silently. This bead reuses it and defines nothing.

GUARD is a flag, not a month's work — spends_the_month already says so, and a guard can tax as well — so Guards (102) works too. The student spends its month and is untouched. Wages arrive in the turn's last phase, so they pay upkeep but cannot fund this month's purchases; late_income already models exactly that and is the path this goes through.

The tension this creates

The shipped unit-does-nothing check tells you a unit “has no order that spends the month” — and it uses the very same spends_the_month. So the units this bead starts paying wages to are exactly the units that check flags.
