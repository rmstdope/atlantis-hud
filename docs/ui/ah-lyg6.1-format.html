The mage sheet file — three shapes

The same two mages in each: Four of Nine (1295) and Whisper (3702), taken from a real fixture report. The player sees this file — they mail it, and an ally may well read it before opening it — so the shape is worth choosing rather than defaulting to.

Every shape carries the same facts, because the planner needs all of them: the unit's number and name, where it stands and whether it is inside a structure, every skill with its accumulated study points (FORC 3 (180) — the level alone is not enough, since 105 and 175 are both level 2 and a month apart), what the report says it may study, and what it is studying now.

Option 1 — the game's own report syntax

What the map export already does: a marker comment on the first line, and a body the existing report parser reads without a new parser being written at all.

OPTION 1A report fragment

Rides the whole existing road — the parser, the classifier, the import prompt.
; Mage sheet from Atlantis HUD
; Borg (21), turn 23

1:7,53 (plain) in Anduin, contains Fort [2].
  - Four of Nine (1295), Borg (21), behind, leader [LEAD]. Skills:
    force [FORC] 3 (180), pattern [PATT] 2 (130), illusion [ILLU] 1
    (40), weather lore [WEAT] 1 (65), fire [FIRE] 2 (90), spirit
    [SPIR] 2 (120). Can Study: fire [FIRE], force shield [FSHI],
    farsight [FARS], necromancy [NECR].
  - Whisper (3702), Borg (21), behind, leader [LEAD]. Skills:
    pattern [PATT] 2 (95), spirit [SPIR] 1 (30). Can Study:
    manipulation [MANI], spirit shield [SSHI].
  • No new parser and no new file type: parseReport already reads this, and every mage arrives as an ordinary ReportUnit that magesOf() understands unchanged.
  • An ally on a different build, or on no client at all, can read it and even hand-write it.
  • It looks like Atlantis, which is what the player is already reading all day.
  • Verbose: a faction with 12 mages writes a long file.
  • Structure membership rides in as the region's contents, exactly as a report says it.

Option 2 — JSON

What the army export does. A shape written for a machine.

OPTION 2A JSON document

Explicit, compact, and versioned — but a new parser, a new validator, and a new set of refusal messages.
{
  "atlantisHudMageSheet": 1,
  "faction": { "id": "21", "name": "Borg" },
  "turn": 23,
  "mages": [
    {
      "unitId": "1295", "name": "Four of Nine",
      "regionId": "1:7,53", "structure": "Fort [2]",
      "skills": [
        { "tag": "FORC", "level": 3, "points": 180 },
        { "tag": "PATT", "level": 2, "points": 130 }
      ],
      "mayStudy": ["FIRE", "FSHI", "FARS", "NECR"],
      "studying": "FIRE"
    },
    {
      "unitId": "3702", "name": "Whisper",
      "regionId": "1:7,53", "structure": "Fort [2]",
      "skills": [
        { "tag": "PATT", "level": 2, "points": 95 },
        { "tag": "SPIR", "level": 1, "points": 30 }
      ],
      "mayStudy": ["MANI", "SSHI"],
      "studying": "PATT"
    }
  ]
}
  • Says exactly what it means. Nothing has to be inferred from prose, and a field can be added later without ambiguity.
  • A version number, so a newer client can refuse an older sheet by name.
  • A whole new read path: parse, validate, and a refusal message for every way it can be malformed.
  • An ally reading it in an email sees braces. It cannot be hand-written by somebody without the client.

Option 3 — a plain listing of our own

Neither the game's syntax nor JSON: a short line-based format written to be read by a person first.

OPTION 3One block per mage

Compact and legible. A small parser of our own — perhaps thirty lines — and refusal messages we choose.
; Mage sheet from Atlantis HUD
; Borg (21), turn 23

1295 Four of Nine
  in 1:7,53 inside Fort [2]
  FORC 3 (180), PATT 2 (130), ILLU 1 (40), WEAT 1 (65)
  FIRE 2 (90), SPIR 2 (120)
  may study FIRE FSHI FARS NECR
  studying FIRE

3702 Whisper
  in 1:7,53 inside Fort [2]
  PATT 2 (95), SPIR 1 (30)
  may study MANI SSHI
  studying PATT
  • The most readable of the three in an email, and the shortest.
  • Hand-writable, and obvious what to correct if a line is wrong.
  • A parser and a validator of our own after all — the same cost as JSON without JSON's free syntax errors.
  • A third file syntax in a repository that already has the game's and JSON.
