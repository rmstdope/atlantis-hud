Clicking a unit number in a problem list — proposals (bead ah-87he)

The problem lists name the unit at fault by number, and the number is inert: you read which unit has the problem and then go and find it yourself. Make it a link that selects the unit — and, from the top bar, moves the selected hex to follow it.

This matters more this week than last. The five warnings added over the last two days all name a unit by number, so there are considerably more inert numbers in front of you than there were.

The focus ring is the same in all three — a brass outline, matching the panel titles' focus-visible:outline-brass. The number becomes a real <button>, so it is tab-reachable and works on Enter and Space, whichever treatment is chosen.

§2  The numbers inside the message the question the bead does not ask

Several warnings name a second unit in their text — the one being helped, taught, or given to. Those numbers are just as inert, and just as much a thing you would want to jump to.

The catch: the messages are plain strings built in Rust, so making the embedded numbers clickable means parsing them back out of prose with a pattern like /\bunit (\d+)\b/. That works today and breaks silently the first time a message is reworded — and one of them (“unit 9002 is not in this hex”) names a unit that is not there to select.

§4  A precedent I found after you chose the app already has this exact control, in brass

The turn-messages panel already turns a unit id into a way to go and look at it — TurnMessagesPanel.tsx:171-207, a <button> classed text-brass hover:underline. Its doc comment even settles the absent-unit case: “Only when the loaded turn actually describes it. An id from an order for a unit that has since died would be a button that does nothing, which is worse than plain text saying the same thing.”

So the same gesture would read brass in one panel and blue in the other. Blue is not arbitrary either — the units table draws an own unit’s id in text-select — but these two lists sit side by side in the header.

Whichever wins, the absent-unit rule is settled by the precedent: a number naming a unit the report does not describe renders as plain dimmed text, not a button. That is what makes §2's “every unit number” safe — “unit 9002 is not in this hex to be taught” simply is not a link.
