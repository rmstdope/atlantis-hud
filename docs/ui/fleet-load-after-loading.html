The load a fleet sails with — what the player reads (bead ah-eet)

ah-j0e warns on a SAIL when a fleet is overloaded, weighing the units aboard at the weights the report printed for them. ah-eet prices this month's orders into those weights, so the load compared against capacity is the load at sailing time. Nothing new appears in the interface — same warning code, same toggle, same place. What changes is the number, and this page is the record of what the navigator decided it should say.

Decided, 2026-08-17, over three rounds. (1) The number is shown as a sum, so the first figure agrees with the Load: line the report printed alongside it. (2) Everything the ledger prices counts — GIVE, TAKE, BUY and SELL; the bead's own premise, that the server runs the market after movement, is wrong, and the rules' Sequence of Events puts buying and selling in phase 7 against movement in phase 9. (3) The verb is loaded / unloaded. (4) An order nothing can price falls back to the report's weights rather than silencing the fleet, so this bead only ever adds warnings and never removes one. (5) Below: a unit boarding counts as weight loaded, which keeps the first figure equal to the report's own in every case.

The marines board and are handed the grain. At sailing time the Cog carries 110 + 200 + 2500 = 2810 against 750. Both options below warn; they differ only in how the 2810 is split.

How the number is split Option 2 was chosen

OPTION 1 — rejected First number = who is aboard, at report weights

Sum the report weights of every unit aboard once ENTER/LEAVE have run, then add what this month's orders moved. Boarding is part of the first number; gifts and purchases are the second.

Problems
11125⚠Cog [329] is overloaded: 310 aboard plus 2500 loaded this month, on a capacity of 750, so it will not sail
report: Load: 110/750 warning: 310 aboard ← disagree
  • One definition of the first number, always — no dependence on whether the report stated a Load: line.
  • Leaves ah-j0e's shipped message untouched: a fleet overloaded purely by boarding still reads 310 aboard on a capacity of 750, exactly as yesterday.
  • The moment anyone boards, the first number stops matching the report — which is the property you picked “show the sum” to get.

OPTION 2 — chosen First number = the report's own Load:

Take the first number of Load: 110/750 verbatim, and let the second number carry everything this month changed — boarding, leaving, gifts, purchases, sales alike. A boarding unit is loading the ship, so it counts as loaded.

Problems
11125⚠Cog [329] is overloaded: 110 aboard plus 2700 loaded this month, on a capacity of 750, so it will not sail
report: Load: 110/750 warning: 110 aboard ← agree
  • The first number is quoted from the report, so the two always agree on screen — the property you chose this shape for.
  • “2700 loaded this month” is the whole of what the player did, in one figure they can go and check.
  • Rewords a message that shipped yesterday: a fleet overloaded purely by boarding changes from 310 aboard on a capacity of 750 to 110 aboard plus 200 loaded this month….
  • A fleet whose report states no Load: line has no number to quote, and falls back to Option 1's definition.

The narrow window checked in the code, not guessed

It wraps, it does not truncate

ProblemsPanel.tsx:83 renders the message in a plain flex row with no truncate and no whitespace-nowrap, so a long message wraps onto a second line and the unit number stays put in its own column. Nothing is hidden at any width. The longest of the three sentences costs one extra line in the panel.
