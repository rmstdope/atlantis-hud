§4  The wrap rule :174 exists because “Atlantis HUD” splits badly

GitHub renders a newline inside a paragraph as a line break, so a hard-wrapped comment arrives ragged — and a wrap landing mid-name gives a reporter Atlantis on one line and HUD on the next. The current rule is written around that specific name.
a wrap that lands mid-name, today: _Written by **Moira**, an AI agent that triages issues for Atlantis HUD. Replying here reaches a human maintainer._
Whatever you choose in §2, the rule has to survive a name of any length — a consumer called a or The Very Long Name Of Someone's Weekend Project. The honest fix is “never hard-wrap these heredocs at all”, which is already what the file says (“the long lines in these heredocs are deliberate; do not reflow them”) — stated as a rule about the heredocs rather than about one name. Say if you would rather it stayed a rule about names.
