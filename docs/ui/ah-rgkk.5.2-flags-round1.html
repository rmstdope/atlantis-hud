ah-rgkk.5.2 — round 1: the Flags popup

Resting on the Flags cell today opens one line — flags  on guard · behind · taxing — with was: behind, taxing dimmed after it. Two comma lists, and the reader diffs them by eye. This bead gives each flag a line of its own that says whether the month set it, cleared it or left it alone, and which order did it.

Three questions. Q1 — which flags get a line. Q2 — how a flag’s state reads on the right. Q3 — what to say about the seven flag orders this preview does not work out at all. Everything else in the family is settled and is not re-opened: the heading, the twelve-line cap, the before → after pair with green up and red down on the after only, and the dim trailing clause.

The scene, used in every panel below. Braves (1487)’s report shows it behind and taxing — the Flags cell reads BT. This month you write GUARD 1, BEHIND 0 and SHARE 1. It ends the month guarding, sharing and taxing, and the cell reads GST.

What the letters hide. BT becoming GST is four separate events, three of which you caused. Nothing on the screen today separates them, and nothing says which order did which.

Q3 — the seven flag orders this preview does not work out

The preview applies four flag orders and no others. GUARD, AVOID, BEHIND and SHARE change a flag; AUTOTAX, NOAID, CONSUME, REVEAL, SPOILS, HOLD and NOCROSS are all real orders (rules/autotax, rules/noaid, rules/consume, rules/reveal, rules/spoils, rules/hold, rules/nocross) that this application accepts, validates — and then shows no effect for. Write AUTOTAX 1 and the Flags cell does not move. This bead cannot fix that (it would be work in the Rust core); it can only decide whether the popup admits it.

All three panels use F1 and V1. The unit here is Watch (1604), which is behind and whose only order this month was AUTOTAX 1 — so nothing at all moved.

  • A flag cleared by the other order names that order. rules/guard and rules/avoid both say “The Guard and Avoid Combat flags are mutually exclusive; setting one automatically cancels the other”, so an AVOID 1 that clears guard says AVOID 1 on both lines rather than inventing a GUARD 0 you never wrote.
  • The cause is the order as you would type it — GUARD 1, BEHIND 0 — not prose such as your guard order. It is the shortest true thing, and it is the line you would go and look for.
  • Line order: the flags the month changed first, then the ones it left alone, each block in the Flags column’s own letter order (A B G H N X R S T C F), and the letterless flags last. Same shape as every other popup in the family: this month first, then the rest.

  • A unit that ends the month with no flags at all still shows the ones the month cleared, followed by “No flags set.” — the second panel above.
  • A foreign unit gets exactly the same popup. A report prints another faction’s flags, and none of your orders can move them, so every line reads unchanged.

One thing this bead deliberately does not do: GUARD 0 and AVOID 1 currently fail to clear a guard flag the report printed, because the core matches the order’s word guarding against the report’s word on guard. That is a defect in the Rust core, not in this popup, and this popup will keep agreeing with the cell it explains rather than contradicting it. I am filing it as a separate bug bead for you to rank.
