ah-lbd9.4 — Option B: sign in first, then Send

Send is switched off for a New Age game today, because the ruleset declares no upload address. This bead turns it back on by a different road: the REST API, with the bearer token ah-lbd9.2 produces. This page is one of two shapes. In B, Send stays off until you have signed in from the header chip, and says so when you hover it — signing in is a thing you do once, in the place the application already has for it, and Send is then the one-field dialog it has always been. The verdict comes back in the same monospace block the New Origins send already uses. Compare with Option A, where Send is always live and the dialog signs you in as part of sending, and the verdict comes back as a sentence and a list.

Already decided and not being reopened: credentials are never stored; New Age is desktop only; one step, not two — Send posts the orders and then shows what came back, and the check-without-saving endpoint is deliberately not used; and when a session runs out, the surface you are already in asks for it (E1) rather than sending you back to the header.

The awkward fact this whole page is about: the world can save orders it also thinks are wrong. It keeps them as long as the #atlantis … #end envelope, the faction id and the password are right, and tells you separately how many syntax errors it found. So the answer is never a simple yes or no, and there are three outcomes to tell apart, not two.

1 · The header

Send is a gate, and the gate is the sign-in you already have. Hovering a disabled Send says exactly what to do about it.

B — signed outSend is off, and says why

The order of the header reads as the order of the work: sign in, then send.

ImportExport ▾ Sign in to ArcanumSend⚙
Sign in to Arcanum before sending orders to it.

The tooltip is the whole of the explanation, and the control it names is two inches to the left.

B — signed inSend wakes up

Signing in is what turns Send on, which makes the chip worth having beside it.

ImportExport ▾ Merchant Guild ▾Send⚙

Send is then off only for the reasons it is off today: no orders written, or an #atlantis line naming no faction number.

2 · The dialog, before you press Send

One field, always. The faction number is never asked for here — the session already knows which faction you are. The password is asked for every time: it is not the token, it is the word that gets written into the #atlantis line of the file the world saves, and nothing keeps it between sends.
