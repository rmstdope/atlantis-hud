Reordering columns — showing the drag while it happens

A grip in each header lets a column be dragged to a new position. PR #421 built this and it worked, with one flaw the review caught: nothing moved until you let go. The handle recomputed the order on every pointer move and only committed on release, so you were dragging blind.

The arithmetic is already right — dragColumnOrder works out the new order on every move, and swaps when you have dragged past the whole of a neighbour. What is missing is showing you the answer it has already computed. Three ways to show it, below.

The example throughout: dragging Long order leftwards, far enough to have crossed Items and Skills. The ownership marker * never moves.

1 · How the drag shows itself

AThe table reorders live

The columns actually move as you drag. What you see mid-gesture is exactly what you get on release; letting go changes nothing on screen, and Escape puts it back.

  • Matches the resize gesture, which already writes live; the two feel like one table
  • Nothing new to draw: the machinery already computes this order on every move
  • Columns jump under the pointer as thresholds are crossed, which can feel busy
  • The whole table repaints on each swap, not just the header

BA drop line between headers

The table stays put; a brass line marks where the column will land, and the column being dragged dims.

2 · Where the grips sit

Two gestures now live in one header cell. They must not have to guess what a press meant.

* Id Unit Men Long order
*13797WoodsmenY2produce yew
  • The reorder grip is the dotted handle at the left of each label; the resize handle is the bar on the right edge, on the boundary it moves
  • The * column has neither: it never moves, and its right boundary is the Id column's to resize
  • The last column has a reorder grip but no resize handle — there is no boundary to its right

3 · The reset, now that there are two things to reset

ah-1owr.2 puts "Reset widths" in Settings, beside Interface size. Order is a separate preference — resizing never implies reordering — so there are two things a player might want back.
