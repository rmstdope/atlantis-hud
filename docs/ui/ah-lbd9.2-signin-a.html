ah-lbd9.2 — Option A: sign in from the header

The HUD has no login surface today. This page is one of two shapes for adding one. In A the sign-in is a control in the header, beside Send, and it doubles as the place that tells you whether you are signed in. Compare with Option B, where the same fields live in Settings › Per game and the header gains nothing.

Already decided on the parent bead and not being reopened: the faction number and password are never stored — no keychain, no settings file, no “remember me”; they are typed once per run of the app. And New Age is desktop only (the world refuses the live web origin), so nothing on this page exists in the browser build.

Chosen (2026-09-04): A — the header control; E1 — the session is asked for again inside the dialog you are already in; S2 — one session per game. The faction number is prefilled and the app writes its own sentence on a refusal. Round 2, which settles the control’s words, is ah-lbd9.2-words.html.

The header’s right-hand group, which today is Import · Export · Send · ⚙. A fifth control joins it, present only for a game played under a New Age world, and only on the desktop build.

4 · Choice 2 — what happens when the session runs out

A New Age token expires and the world offers no way to renew one, so the answer is always “sign in again”. The question is where that is asked. This matters beyond this bead: it is what ah-lbd9.3 (fetch the report) and ah-lbd9.4 (send orders) will have to do when a call comes back unauthorised.

E1Ask again where you are

The dialog you are already in turns into the sign-in prompt, and does what you asked once you are back in. Nothing you typed is lost, and you never go looking for a control.

Costs: the sign-in prompt has to be embeddable in two other dialogs, so ah-lbd9.3 and ah-lbd9.4 each carry a little more.

E2Say so, and put you back in the header

The action stops and says why; the header chip returns to Sign in. You sign in there and ask again.

5 · Choice 3 — you have more than one game open

The HUD holds several games at once, and two of them can be different factions on different worlds.

S1One session at a time

Signing in belongs to the game you were in. Switch game and the chip reads Sign in again — the other session is forgotten there and then.

Simplest, and there is only ever one token in memory. The cost: two Arcanum factions means retyping a password every time you switch between them.

S2One session per game

Each game remembers its own signed-in faction for as long as the app is open. Switch back and forth and both stay signed in.

A little more to hold, and still nothing on disk. The cost: several tokens in memory at once, all dropped when the app closes.

Mockup only — no build step, no external assets. Colours and spacing are the app’s own.
