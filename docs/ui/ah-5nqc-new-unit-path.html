A new unit's path starts where it was formed

A player forms NEW 1 in several hexes — one FORM 1 per hex is a common habit — and gives just one of them a MOVE. Select that unit and the map draws its path from the northernmost hex with a New 1 in it, not from the hex it was formed in.

Why: movement tells new units apart by their number only, so every New 1 on the map becomes one unit, and whichever hex it happens to land on wins. When two New 1s both move, their moves can even run together into one strange path.

The example throughout. Three hexes, each with a unit that writes FORM 1: forest (4,20) in the north, plain (5,23), and hills (6,26) in the south. Only the New 1 in hills (6,26) is told MOVE N N.

Question — does anything else change? Chosen: A, just the fix

The fix itself is not in doubt. What is open is whether the player is also told that the same number is in use elsewhere.

A Just the fix

Each New 1 draws its own path from its own hex, and nothing new appears anywhere. Units table unchanged.

B The fix, plus a quiet note on the row

Same fix; each new unit whose number is also used in another hex says so beside its name.

  • Makes the repeated number visible.
  • New words on every such row, for something that is not a mistake; the table gets wider.

The states behind the example

  • Two New 1s both move — forest's goes MOVE S, hills' goes MOVE N N. Each selected on its own shows only its own path, from its own hex. The moves never run together.
  • A New 1 with no MOVE (the plain one), selected — no path, as today for a new unit that stays put, even though another New 1 elsewhere moves.
  • The units table — each moving New 1's destination is worked out from its own hex too, so hills' row reads → swamp (6,24), not a hex two north of the forest.
  • Only one hex uses New 1 — nothing changes from today.
