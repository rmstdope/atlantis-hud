Fetching this turn's New Origins report

Today a New Origins report reaches Atlantis HUD only by way of a browser: open the game's site, press the download button for your faction, type a password, save the file, come back and drop it on the window. Every turn.

The New Age worlds already do this by themselves — one Fetch button, a faction number, a password, and the report lands. This page is the agreed shape of the same thing for New Origins. Chosen 2026-09-09 across four rounds and amended 2026-09-10; every string here is quoted as it will ship, not paraphrased.

Fetching is one single request. The faction number and the password go with the download itself — there is no signing in to New Origins, and no step before the fetch. That is why there is one working line rather than two, and one failure message rather than three.

Scope is fetching this turn only. Sending orders back, and pulling earlier turns into the game's history, are separate pieces of work.

1 · Where it lives

The header is untouched. The same Fetch button, in the same place, doing the New Origins thing when the open game is a New Origins one.

5 · When it goes wrong

Three failures. A refusal and an unreachable site keep the dialog open for a second try; an unreadable reply says what still works instead.

refused

A wrong password and a turn that has not been generated yet come back as the same thing: an ordinary web page carrying a red block. Rather than guess which, the site’s own sentence out of that block is the message, word for word — the same thing sending orders already does today.

Faction password is incorrect.
and when the reply carries no sentence of its own
New Origins would not give up this turn’s report. Check the faction number and password.

Password cleared and refocused, faction number kept: a typo is far and away the commonest reason this appears.

unreachable

Could not reach atlantis-pbem.com.

Both fields keep what you typed, so pressing Fetch again is the whole of the retry.

unreadable

atlantis-pbem.com answered with something Atlantis HUD could not read. The site may have changed — downloading the report in a browser and dropping it here still works.

The one failure New Age does not have. Never a dead end: it names the way round.

7 · Considered and rejected

  • Keeping the two what-to-fetch choices. New Age offers this turn, or this turn and every earlier turn not yet loaded. Earlier turns are not being built here, and a choice of one — or a second line permanently greyed out — offers something and refuses it every single turn. The choices appear when there is a second one to make.
  • A second Fetch button beside the existing one. New Origins is another kind of place the same button learns, not a second path in the header. One place, one habit.
  • Naming the game in the heading alone, without the faction line — rejected in favour of the line that confirms you are about to fetch for the right faction, since a mistyped number is the mistake this control invites.
  • Letting a fetch replace the screen silently, exactly as a dropped file does. Rejected: a dropped file is a file you chose by hand, and a fetch is a number you typed. The confirmation is the only place this diverges from the shared front door, and it is deliberate.
  • Warning before the fetch instead of after it — a line in the form saying what pressing Fetch will do. Rejected: it warns about a replacement that may never happen, since the report might be an older turn or somebody else's.
  • Asking from the strip under the header rather than in the dialog. Rejected: nothing is on screen while you decide, which makes it easy to walk away leaving it half done.
  • Asking about an older turn too. Rejected: nothing on screen changes, so it is a question whose answer is always yes.
  • Throwing away a report you declined to open. Rejected: it is already fetched and read, and fetching it again costs the password and the wait a second time.
  • One message for every failure that is not a refusal. Rejected: a site that is down and a site that has changed want opposite things done about them, and only one of them is worth waiting out.
  • Two working lines, signing in then fetching. Rejected on fact: there is one request, so the first line would describe something that never happens.
  • Asking New Origins for this turn's report… as the working line, naming who is being waited on rather than what is being done. Rejected in favour of the line that reads the same as the New Age worlds' own.
  • A second, past-tense refusal — New Origins stopped accepting that faction number and password. — for a password that fails after signing in worked. Rejected on fact: there is no after.
  • Two separate outcomes for a refusal and for a turn that is not ready, a red message in the dialog and a status line with the dialog closed. Rejected: both arrive as the same kind of page, and nobody has yet seen the wording that would tell them apart. Quoting the site says the truth without guessing.
  • One sentence of ours covering both — either the faction number and password are wrong, or this turn has not been generated yet. Always true and never wrong, but it puts a question in front of a player every time, including for an ordinary typo, when the site itself usually says which it was.
  • Leaving the password as typed after a refusal, on the grounds that it may have been right and the turn simply not ready. Rejected: a typo is far and away the commonest cause, and clearing is what the field already does.
  • Calling the far end "the game" or "atlantis-pbem.com" in the refusal. Rejected: "game" also means the thing open in the HUD, and an address is the wrong subject for a password being refused.
