This page is the record of the decisions that settle it: the two taken on 2026-08-29 while splitting ah-vcp8, and the three taken while planning this bead.

Decision 1 & 2 — settled on splitting ah-vcp8 (navigator, 2026-08-29)

1. A unit number the report names nowhere: the order does nothing. No charge, no credit, no movement and no doubt marker — the row reads exactly as it would with the order deleted. Rejected: charging the giver, which is alarming and wrong when the player simply mistyped a number, the commoner mistake; and showing ? with a doubt marker, which was offered and set aside.

2. A unit the report does show but we cannot project: the goods leave, and no row of ours gains them. An ally standing here, and FACTION 2 NEW 1, which the game creates here. The giver's row empties exactly as it already does for a GIVE 0 discard. Rejected: leaving both alone, which would show a player still holding ten swords they have given away. No new wording — the ITEMS cell's own was: tooltip carries it.

So there are three cases where there are two today, one classification written once and read by all four surfaces: ours (charge the giver, credit the receiver), shown here but not ours (charge the giver, credit nobody), and named nowhere in this region — which now also covers a NEW alias no FORM here creates, and a unit giving to itself, which the server refuses.

Decision 3 — men are ordinary goods in this bead

“First, silver may be given to any unit, regardless of factional affiliation. Second, men may not be given to units in other factions (you must give the entire unit); the reason for this is to prevent highly skilled units from being sabotaged with a GIVE order.” rules/give — NewOrigins v8.0.0, committed snapshot. rules/exchange agrees: “Men may not be exchanged.”

Decision 2 is right for iron, swords and silver and wrong for men: the game refuses that half of the order. Three readings were put to the navigator — reuse the existing items-cannot-be-given sentence, name the reason in a new one, or say nothing.

Chosen: none of them, here. Men are treated as ordinary goods in this bead, and the refusal is ah-8lej, filed unranked, which carries the three wordings above for its own planning session. This bead therefore ships one case it knows to be wrong, deliberately and on the board rather than in somebody's head.

Decision 4 — GIVE NEW 3 when no FORM 3 exists in this hex

NEW 3 is named nowhere in this region, so decision 1 applies: the order does nothing. But it differs from a mistyped unit number in one way. A mistyped number already gets give-target-not-here, so the player is told; that check deliberately passes over NEW n, because an alias names nothing the report could show. Left alone, an unformed alias would be silent everywhere — no charge, no movement, no warning. The order would simply disappear from the screen.

Decision 6 — a warning that starts firing on its own

Let it fire. Once a gift to an ally really empties the giver, a SELL written below it has nothing left to sell, and nothing-left-to-sell already knows how to say so. No new wording; the sentence already ships for GIVE 0 and for a faction-mate's TAKE. Rejected: suppressing it for this one target, which would leave the SELL row promising income the server will not pay.
