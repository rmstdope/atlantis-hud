The phase vocabulary — a closed list, or not

Every agent reports what it is doing through scripts/agent-state <Name> working --phase <word>, and the fleet view shows that word in the State column. agent-state holds the eighteen legal words as a literal case and exits 2 on anything else; emacs/cerebro.el holds the same eighteen in cerebro--phases, and a test asserts the two lists agree.

A consumer of cerebro that adds a role of its own — an archivist, a release manager — invents a phase word for it, and that role cannot report state at all. It exits 2 on every call, so it never appears as working in the fleet view.

agent-state's own comment already concedes the vocabulary "is not checked per-role — any of the words above is accepted from any name". So today an implementer may report weekly and a planner merge, and the list catches neither. What it catches is a typo: --phase plna.

1 · What replaces the closed list

The trade is the same in every option: catching a typo, against letting a role that cerebro does not ship report at all.

AA shape check

Any lower-case word is accepted; the list goes from both the script and the elisp, and the test that kept them in step goes with it. A typo simply appears in the State column.
Agent      Role       State      
Cyclops    implemen…  working    gate
Xavier     planner    working    plna
Archivist  archivist  working    index

a typo shows; a new role works
  • A consumer role works the day it is written, with nothing to declare
  • Deletes a list from bash, a list from elisp, and the test holding them together
  • A typo reaches the fleet view instead of failing at the call
  • Nothing anywhere now says what the words are — the docstring was the reference

BWarn, do not refuse

The list stays as a reference. An unknown word is written to the state file as asked, and a line on stderr says it was not recognised. Nothing exits 2.
$ agent-state Xavier working --phase plna
agent-state: phase 'plna' is not one
  of the known words - writing it
  anyway

$ agent-state Archivist working \
     --phase index
agent-state: phase 'index' is not one
  of the known words - writing it
  anyway
  • Keeps the typo signal and never blocks a consumer's role
  • The list survives as documentation of what this fleet uses
  • A consumer's own role warns on every single call, forever
  • Two lists still to keep in step, for a check that no longer decides anything

CA consumer file, like the roster

A tracked .claude/cerebro-phases that adds to the built-in words, exactly as .claude/cerebro-roster replaces the built-in fleet (ah-qled.5.1).
.claude/cerebro-phases

publish

$ agent-state Archivist working \
     --phase index
ok
$ agent-state Xavier working --phase plna
agent-state: unknown phase 'plna'
exit 2
  • Keeps the refusal, so a typo still cannot reach the fleet view
  • The same pattern a consumer already learned for the roster
  • A second config file, for eighteen words nobody looks at
  • The elisp must read it too, or the fleet view and the script disagree

2 · The guard that keeps the two lists in step

cerebro--phases in the elisp is used by no other elisp — but tests/launchers.sh asserts that every phase any shipped agent file mentions appears in it. So it is unused code holding a live check: if an agent definition starts using a word that agent-state would refuse, the test says so.

iKeep the guard, whatever happens to the list

The test keeps asserting that the words the shipped agents actually use are words agent-state accepts — rewritten against whatever mechanism section 1 chooses.
PASS every phase used by a shipped
     agent file is one agent-state
     accepts
  • The real value is caught: an agent asking for a word the script refuses
  • Survives all three options in section 1
  • Under option A it becomes nearly vacuous — everything is accepted

iiLet it go with the list

If section 1 removes the refusal, there is nothing left to be out of step with: delete cerebro--phases, its test, and the mirroring.
- defconst cerebro--phases
- the launchers.sh case
- the mirrored list in agent-state
  • Nothing left to drift, because nothing is duplicated
  • Least code by a distance
  • An agent file naming a phase the fleet view renders oddly is no longer caught
