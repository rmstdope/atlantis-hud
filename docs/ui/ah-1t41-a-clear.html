ah-1t41 — option A: changing the source empties the box

The units pane's filter box keeps whatever was typed into it when the list underneath it is replaced. This page is option A: clicking a different entry in the source rail clears the box, so the new list arrives whole. Option B is the other file — each source keeps a filter of its own.

Open both before answering. The difference is entirely in what happens on the way back, and that is the part a description cannot carry.

  • Nothing to learn. A list you have just asked for is the list you get.
  • One rule, one sentence, and it matches the pick: ah-1mpx.4 already clears the multi-select when the source changes.

  • Nothing is announced. There is no toast and no "filter cleared" line.

The states this has to answer either way

Every row here is a question the implementer cannot answer from the sentence "clear the filter". The recommended answer is the one in the third column.

What happensDoes the list change?Recommended
Click a different rail entryYesClear
Click the rail entry you are already onNo Keep. Today the two built-in entries already ignore this; an Army does not, so the same click behaves differently depending on which entry it is. Either answer must be made to hold for all three.
Select a different hex on the map, while This hex is the sourceYes — entirely Keep, by recommendation — but this is the real question. Filtering on a name and then walking hexes is a way of asking "where are my scouts", and clearing would end it. It is also, on the face of it, the same defect.
A new turn's report loadsYes, mostlyKeep. Nothing was clicked.
The Army being shown is deleted, and the table falls back to This hexYes Clear. The list was replaced, exactly as if the rail had been clicked.
The sort column— Unchanged, by recommendation. A sort already resets when the new source stops drawing the column it sorts on, and a sort on Name still means something on any list. Clearing it too is defensible and is a separate decision.
The selected unit— Unchanged — today's behaviour, out of scope here.

Where the focus goes

Clicking a rail entry moves focus to that entry, and neither option changes that. The box is emptied without being focused, so nothing is typed into it by accident and the keyboard stays where the player put it.
