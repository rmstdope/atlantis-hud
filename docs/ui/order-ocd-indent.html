Order OCD — indentation, and the newline at the end

Two additions to a setting that today only shouts keywords. One space per nesting level inside FORM…END and TURN…ENDTURN, and exactly one newline at the end of a unit's orders, so clicking in the empty space below the last order puts the cursor on a fresh line rather than at the end of the last one.

Everything below is one unit's block as the editor shows it. The existing tidy runs when the unit is next opened, when the setting is switched on with a unit already open, and when the core's word list arrives late — that is the behaviour ah-1znc settled, and these two additions can either join it or run on their own clock.

1 · When the indentation is applied

The player typed this, flat, with no indentation — and in the third line, four spaces of their own. What should the editor do with it?

AOnly as you type

Pressing Enter inside a block opens the new line already indented to that level. Nothing that is already on screen is ever touched.

FORM 1
STUDY COMBAT
END
ENDTURN
(unchanged — new lines only)
  • Never fights the player over text they wrote deliberately
  • No surprise edit when a unit is opened
  • A half-written turn stays mixed — the exact thing rejected in ah-1znc
  • Imported orders and pasted text are never tidied at all

BOn open, the whole block re-indented

The indentation is recomputed from the block structure whenever the case tidy runs — every leading space is replaced, whatever the player put there.

FORM 1

END

 END
ENDTURN
  • One rule, one look — imports, pastes and hand-typed text all end up the same
  • Exactly the promise the case tidy already makes
  • The player's own four-space indent is thrown away without asking
  • A block only opens correct-looking after you click away and back

2 · Where the closing keyword sits

Whichever of the above: FORM opens a level and END closes it, so END could belong to the level outside the block or to the level inside it.

iCloser aligns with its opener

Only the block's contents are indented. This is how every programming editor lays out a brace.
TURN
 NAME UNIT "Scout"
 FORM 1
  NAME UNIT "New"
  STUDY COMBAT
 END
 MOVE N
ENDTURN
WORK
  • The pair brackets the indented run, so a missing END is visible at a glance
  • What a player who writes code will expect

iiCloser sits with the contents

Everything between the opener and the closer, closer included, moves in one level.
TURN
 NAME UNIT "Scout"
 FORM 1
  NAME UNIT "New"
  STUDY COMBAT
  END
 MOVE N
 ENDTURN
WORK
  • "Everything inside the block is indented" is a simpler sentence to hold
  • The closer no longer lines up with anything, so an unclosed block hides

3 · The newline at the end

The ask is a symptom: click in the empty space below the last order and the cursor should be on a fresh line. That happens when the block's text ends in a newline. Today it does — but only after a save has landed, and nothing removes extra blank lines the player left behind while they are still in the editor.

iFixed up with the rest of the tidy

When the block is tidied — on open, on the setting being switched on — the trailing blank lines are collapsed to exactly one newline. While typing, Enter behaves normally.
