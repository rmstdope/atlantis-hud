Round 3 — the rules of the repair

Bead ah-ty3s. Rounds 1 and 2: docs/ui/ah-ty3s-formed-unit-orders.html, docs/ui/ah-ty3s-round2.html.

Settled so far: A1 the formed unit's editor holds the lines between form n and end. B1 the creator's editor is unchanged. D1 all three clicks select the formed unit. E1 emptying it leaves the form/end standing. F1 a finding is underlined only in the editor of the unit it names. G3 a stale unit new-n block is folded back into its form n block on load.

G3 is the one answer that needs its edges drawn before it can be built. It rewrites a file the player saved, so an unattended implementer must not be left to invent what happens when the shape is not the clean one. Below: the cases I intend to settle myself, then the two I will not.

What the repair does mine, unless you object

Run once, on the document as it is loaded — a restored draft, a restored turn, or an imported orders file — and never again while typing. Both halves of an edit go through the same writer that typing does, so the repaired document is saved exactly as an edit would be.

The document saysWhat happensWhy
One unit new-1 block, and one form 1 in the same region Its lines are appended inside that form 1 block, after whatever is already there, and the unit new-1 header is removed. The one case this is for.
An empty unit new-1 block The header is removed. Nothing is moved. There is nothing to move, and the header alone is what the server refuses.
Two form 1 blocks in the same region The first one takes the lines. The core swallows the second: an alias already taken in a region forms nothing (intents.rs:414-418, rules/form). The first is the unit the row belongs to.
A form 1 in another region Not a match; the block is left alone (see Question 7). An alias is scoped to its region (rules/form), so that form 1 is a different unit.
A form 1 nested inside another form Matched like any other: the innermost form 1 the core would count is the one. Nesting is legal and the core already models it (intents.rs:383-390).
A unit new-1 block containing its own form…end Moved with everything else, verbatim. The repair moves lines; it never reads them.
Indentation of the moved lines Left exactly as it was. Whitespace is nothing to the server, and re-indenting is Order OCD's job and the player's setting.

Question 7 yours · A unit new-1 with orders and nowhere to put them

The block has lines in it and there is no form 1 in its region to fold them into — the player deleted the form, or the block was left behind by a turn that has since moved on.

H1 Left exactly as it is

The repair only ever moves lines. A block with nowhere to go is not touched, and stays in the file as it stands.
before
unit 1922 @tax unit new-1 buy 5 plainsmen
→
after
unit 1922 @tax unit new-1 buy 5 plainsmen
  • No line the player typed is ever lost, in any shape the file can be in.
  • One rule to state and to test: no form, no move.
  • The file still exports and is still refused by the server, and nothing on screen says why — the exact gap G1 was rejected for.

H2 Left as it is, and the header says so

Same file, plus one line in the header the next time the game is opened, naming the block and where it is. Nothing is deleted, and nothing is silent.
before
unit 1922 @tax unit new-1 buy 5 plainsmen
→
after — unchanged, and said aloud
unit 1922 @tax unit new-1 buy 5 plainsmen
⚠ unit new-1 has orders but nothing forms it — the server will refuse this block
  • Nothing lost, and the one case the repair cannot fix is the one case you are told about.
  • A header line, not a check in the core — far less than round 2's G2.
  • A warning about a line you cannot see and cannot click to.
My recommendation: H2. H1 is the safe half of it and I would take it if the warning were expensive, but it is one status line on a path that is already computing exactly this fact. The objection — a warning you cannot click to — is real; if you would rather have silence than an unactionable warning, H1 is the honest choice and I will say so in the plan.

Question 8 yours · Whether the ordinary repair says anything

The clean case: two orders moved into form 1, the stale header gone, the file now valid. Your saved file has been changed by opening it.

J1 Silently

Nothing is said. The orders are where they belong and the pane shows them under new 1, which is the whole point.
11 regions · 42 units
  • Nothing to read on a load that went right.
  • A file changed without being asked and without being told — my objection to G3, unanswered.

J2 One line in the header

A notice beside the turn counts, gone at the next thing you do. It names the unit and what moved.
ℹ Moved 2 orders into FORM 1 for new 1
  • The change is on the record at the moment it happens.
  • Reads as a repair rather than as an error, which is what it is.
  • One more line on a load, for something that will stop happening once nobody has an old draft.
My recommendation: J2. The wording, tone and plural handling are mine and will go in the plan's Decided by me; only whether it is said at all is yours. If both blocks and several regions are repaired at once it becomes one line naming the count — “Moved 5 orders into 2 FORM blocks” — rather than one line each.
