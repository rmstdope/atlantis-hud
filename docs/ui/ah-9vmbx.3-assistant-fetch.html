The assistant fetches this turn's report

The assistant asks for this turn's report. The HUD opens its usual Fetch dialog on its own, with one line on top saying the assistant is asking. Typing the password and pressing Fetch is the go-ahead; Cancel is the no. The assistant never sees the password, and it is never kept.

From the moment you press Fetch, it is the Fetch you already know: the same working line, the same refusals, and the same Open / Keep question when a newer turn arrives. Agreed 2026-11-16 over three rounds. Every string is quoted exactly as it will ship.

Desktop application only, as the Fetch button is. On the web version nothing appears, and the assistant is told fetching is not available there.

1 · It asks

The dialog opens straight away, over whatever is on screen, with the password field focused. If the HUD is not the window you are using, its Dock icon bounces (on Windows the taskbar button flashes) until you switch to it. The HUD never comes to the front by itself.

3 · You say no

Cancel or Escape, at any point before the report arrives. Nothing is fetched.

Fetch declined — the assistant has been told.

4 · The assistant stops waiting

When the assistant says it has stopped waiting, the dialog stays open and only the top line changes. Fetching still works and loads the turn, as the header's Fetch does; the assistant just won't hear how it went. Cancelling now says nothing, because there is nobody to tell.

5 · You are already in a dialog

The request waits its turn. Nothing changes until your dialog closes; then the assistant's Fetch opens. If your own dialog was a Fetch that brought this turn, the assistant is told that turn and nothing more opens. A second request while one is already waiting adds nothing on screen.
