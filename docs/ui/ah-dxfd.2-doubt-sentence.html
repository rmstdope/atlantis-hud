ah-dxfd.2 — the sentence the innocent neighbour reads

You chose B: a transfer the app cannot follow makes the hex's combat-ready sum unanswerable, so a pillaging unit's SILVER cell shows ?. I said that needed no new sentence. Checking the code, that was wrong — and it turns out to be wrong for a case that already ships.

When the hex's sum is unanswerable, price_pillage raises SilverDoubt::EstimatedMen, whose hover reads:

This unit's headcount is an estimate, so its month cannot be priced.

The code's own comment says "EstimatedMen is reused rather than a variant added — its sentence stays true." It does not. The sum goes unanswerable when any own unit in the hex has a guessed headcount, so today a unit whose own count is exact can already be told its headcount is an estimate. Option B adds a second cause with the same problem.

S1 — keep reusing EstimatedMen
This unit's headcount is an estimate, so its month cannot be priced.
  • No new string, no new variant, no TypeScript at all — this bead stays inside crates/core.
  • It is false, and demonstrably so: the Raiders' MEN cell shows a plain 12 two columns away while this sentence calls it an estimate. A player who trusts it goes looking for a ~ that is not there.
  • Leaves a defect that already ships, in a comment that asserts the opposite.
S2 — one new sentence for both causes, in the app's own house pattern
Another of your units here cannot be counted, so the combat ready men in this region cannot be added up.
  • Follows the sentence the app already uses for a neighbour-caused doubt: "Another of your units here draws on the same pool and its headcount is an estimate, so this unit's share cannot be worked out."
  • Fixes the case that already ships as well as the one this bead adds — one variant, both causes.
  • Points at the thing the player can act on: it is a neighbour, not this unit.
  • Adds a SilverDoubt variant, so the bead grows a generated TypeScript type and a unitTooltip.ts entry. No longer Rust-only.
  • "cannot be counted" is doing two jobs — a guessed headcount and an unfollowable order — and says which only by being vague.
S3 — one new sentence, and say what is actually unknown
The combat ready men in this region cannot be added up, so what a pillage earns cannot be said.
  • Says exactly what is missing and exactly what it costs, without claiming anything about this unit or guessing at the cause.
  • True of every cause, present and future — a third cause added later needs no new wording.
  • Fixes the shipping case too.
  • Does not tell the player which order to go and look at. They must find the neighbour themselves — though that neighbour's own cell already shows ? with its own explanation.
  • Same TypeScript cost as S2.
