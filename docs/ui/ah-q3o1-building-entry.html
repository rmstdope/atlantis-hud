A building's entry in the dictionary — two corrections (ah-q3o1, ah-rpnb)

Both found by Psylocke verifying ah-5jkt.1, which passed. Same dialog, same few lines, so they are drawn together here — they remain two beads.

Measured from config/public/ruleset.json on main: 58 buildings, of which 36 carry buildSkill and buildLevel. The skill is stored as a tag — BUIL, MINI — so the entry has to resolve it to a name.

Lair — the case that decides §2

Building

Lair

This is a building. Monsters may lair in this structure.

Mages needed0
  • A lair carries no cost, no materials, no size and no build skill. Its entire fields list is one misleading zero.
  • 22 of the 58 buildings are like this.
The label states the opposite of what the number means. It is a capacity — how many mages the structure houses, which is exactly what the magic-study warning reads it for. A Fort silences that warning by sheltering mages, not by demanding them. So Mages needed: 0 tells a reader a prerequisite exists where there is none.

§2  ah-q3o1 — the label, and whether a zero is worth a row the wording is already yours: “Mages sheltered”

— no fields at all —
  • The row appears only where it says something: 8 of 58 entries.
  • Matches every other field in this dialog, which is already conditional.
  • A lair's entry becomes description-only. Honest, but it looks empty.
  • “Does this shelter mages?” is then answered by silence, which a reader has to learn to read.
