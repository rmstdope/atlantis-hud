What the map draws for a qualified structure — the Gateway question (ah-lcyn)

classify() in mapThemes/hexView.ts:207 matches a structure's kind against sets of bare words. Real reports qualify most kinds, so the match fails and the structure falls through to building.

I measured every distinct structure kind across tests/fixtures/reports/*.rep — 100 of them — rather than working from the bead's summary. Everything below is from that.

Seven of ten wrong. Ice Cave and Demon Pit are the sharp ones: cave and pit are already in the set, and the qualifier alone defeats the match.
Two things I found that the bead did not claim, and they are worse.
1. Every single lair-word kind in every fixture carries a qualifier. There is no bare Lair or Cave anywhere. So before #487, LAIR_KINDS matched nothing at all on real data — the lair mark has never once been drawn from a real report.
2. No fixture contains a Shaft kind, or any kind with the word in it. SHAFT_KINDS is {"shaft"} and has never matched anything either. The only line carrying the word is + Central Mine Shaft [10] : Mine, whose kind is Mine.

§2  The Gateway — and a slot that has been waiting for it 28 in the fixtures, the most common qualified kind there is

Every Gateway reports itself as Gateway, contains an inner location, and within the committed fixtures that phrase appears on nothing else — but see the correction in §4: a real report shows a Shaft carries it too, so the phrase means “leads to an inner location” and cannot by itself tell a gateway from a shaft. Meanwhile hexView.ts:107-112 already carries this:

/** Reserved. Every theme's layout keeps a slot for a battle and for a gate; both turn true when the parser learns to read them, and no layout changes when they do. */

The gate field exists, is always false, and every theme already keeps room for it. The badge list deliberately leaves it out because "a control that does nothing is worse than no control". The parser can read a Gateway today.

A A Gateway lights the reserved gate mark

Gatewaygate
Ice Cavelair
  • The slot is already there in every theme, by design, for exactly this. No layout moves.
  • A gateway is the magical way between levels — genuinely a different thing from a shaft, and it reads as its own thing.
  • Turns a documented "reserved, always false" field into a live one, and gate joins the badge list so it can be switched off.
  • Slightly more work than adding a word to a set: a badge, and each theme drawing the slot it reserved.

B A Gateway takes the shaft mark

Gatewayshaft
  • One idea: "a way to another level", however it works. Route planning treats them alike.
  • It would finally make the shaft mark appear — today it never does.
  • Conflates the magical with the non-magical. hexView.ts:60-62 says a shaft is "the only non-magical way between the surface and the underworld", which stops being true.
  • Leaves the reserved gate slot unused for the one thing it was reserved for.

C A Gateway stays a building

Gatewaybuilding
  • No change at all; the smallest possible bead.
  • 28 of them in the fixtures — the most common qualified kind — all drawn as anonymous buildings.
  • A gateway is a way off this level; a player scanning the map for one cannot find it.

§3  A consequence of fixing it properly this is the part worth looking at twice

The robust fix is to match the report's own closed to player units marker rather than a list of names — that is what actually means unenterable monster habitat, which is what LAIR_KINDS is documented as identifying, and it catches all ten including any kind nobody has seen yet. But it means these draw as lairs:

D Everything closed to players is a lair

Giant's Castlelair
Magician's Towerlair
Whirlpoollair
  • Correct by the data's own meaning — the report says these are closed to your units and hold something hostile.
  • An unseen kind can never fall through again, which is the whole point.
  • "Lair" is a strange word for a Magician's Tower or a Giant's Castle, if the mark is ever labelled.

E Lair by marker, but keep a building look for the built ones

Giant's Castlebuilding + hostile
  • A castle still looks like a castle; the danger is a badge on top.
  • A new mark to design, and a second concept to explain. Considerably bigger than this bead.
  • Two ways of saying "you cannot go in here", which is one too many.
§4 — CORRECTED by the navigator, 2026-08-21. I wrote above that no report sends a Shaft. That is true of the committed fixtures and false of the game: report-neworigins-v7-95-55.rep contains

+ Shaft [1] : Shaft, contains an inner location.

So SHAFT_KINDS is correct and will match as soon as PR #487 strips the clause. Two consequences: the fixtures have a coverage hole, not the code — that turn is to be added as a fixture; and “contains an inner location” is carried by both Shaft and Gateway, so the shaft/gate split must key on the kind word, never on that marker.

The source report also carries the faction’s real password on its #atlantis line, and this repository is public. Every committed fixture has it replaced with "<password>"; the new one must be redacted the same way before it is committed.
