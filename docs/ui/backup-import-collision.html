A backup of a game you still have is treated as a restore point: the only offer is to roll the game back to it. Cost: no way to keep both — comparing the backup with the live game means restoring it somewhere else first.

What was decided (2026-08-16)

B was chosen over A (never asks) and C (replace only). The confirmation ships with exactly the words drawn: line 1 ““<name>” is already here. Replace it with the backup, or import the backup as a second game?”, line 2 “Replacing erases its current turns, orders and remembered map.”, buttons Replace / Keep both / Cancel. Keep both imports under a fresh id and is always named “<name> (imported)”. Replacing the open game closes the picker and opens the imported game in its place, discarding unsaved order text (as delete does); replacing another game likewise opens the imported one. Cancel drops the file and leaves the picker on This game with focus back on Import game backup…; Esc closes the picker; focus lands on Cancel when the confirmation appears. Small print under the buttons becomes “Import creates a new game; if it is already here you are asked whether to replace it.”. Separately, the exported file is now named “<game name>.atlantis-hud-game.json” instead of by the game's UUID.
