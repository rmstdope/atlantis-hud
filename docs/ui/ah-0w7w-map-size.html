Telling the app the map's size — proposals (ah-0w7w)

Your words: “when starting a new game, you should define width and height as well as if it wraps on x and y. Default should be 72x96, wrapping on only x.”

This is not only a setup form. movement/graph.rs already names the gap: “Atlantis maps wrap east to west, the rules page never says where the seam is, and a computed neighbour would be wrong exactly at the edge — where being wrong matters most.”

a movement drawn into unexplored country, today: from (71,40) heading east → computed (72,40) ✗ no such hex; the map wraps to (0,40) with a known width of 72 ✓ (0,40)
The module already works around it by taking adjacency from the coordinates the report states — which works wherever you have been. geometric_neighbour() is the deliberate exception for unexplored country, and its own comment concedes: “drawing the intent roughly right everywhere except across the wrap seam beats drawing nothing.”

§4  North–south wrap

You asked for the flag on both axes, defaulting off for y. Worth settling before it is built: if a y-wrap is not a thing an Atlantis map does, an honoured flag is a way to make the movement planner confidently wrong, and a refused one is a checkbox that does nothing. The third option is to offer it and honour it — costing nothing if nobody turns it on.
