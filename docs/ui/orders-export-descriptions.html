Exported orders · where the “keep the descriptions” option lives

The server writes each unit’s own description into the report’s long-format orders template — name, flags, weight, capacity, skills and what the unit can study, wrapped over as many ; lines as it takes. The editor strips it on purpose (#37): the unit panel already says all of it, and on a unit with no orders yet the description is the whole block. But the exported file is read elsewhere — kept as a record of the turn, diffed against the next one, or read by somebody without this application in front of them — and there it is what makes a bare unit 793 legible.

So the option belongs on the export. Three places it could live, drawn in the application’s own palette and widgets. Default is off in all three: today’s output must not change unless it is asked for.

Chosen: A, a second menu item. The export is already a menu that asks which of two things you meant, and a third answer costs the player nothing at the moment they are deciding — no second press, no preference set weeks ago and forgotten. B buys a home for future options that do not exist yet, at a press per turn; C is the least friction and the least visible, and a file’s shape is a per-file question rather than a standing preference.

What changes in the file

Whichever way the option is reached, the output is the same: each unit’s description goes back in verbatim, in the server’s own wrapping, directly under its unit line and above the player’s orders. A unit the template has no description for — one the player raised this turn — simply gets none, and the player’s own ; notes are neither dropped nor duplicated.

Drawn in the workspace palette from packages/shared/src/theme.css; the widgets are redrawn from ExportMenu.tsx, MapExportDialog.tsx and SettingsDialog.tsx. Self-contained: no build step, no external assets, no network. Bead ah-52b.
