Q4 — goods that appear, and goods that run out

Buying and withdrawing put goods in a unit's hands that its report never listed; selling and giving can empty a stock entirely. The ITEMS column is one comma-separated line, so both cases change its shape, not just its numbers.

What GIVE does today. A stock that reaches zero disappears from the line (the report never lists an empty stock, so the preview does not either), and a newly-acquired item is appended at the end. This question is whether those two rules are right now that four more orders can trigger them.

The situation on this page. Farmhands (5518) holds 120 SILV, 12 FUR, 4 LEAT. It is told to sell every fur (the market wants fur at $32) and to buy 5 grain at $18.

unit 5518
  sell all FUR
  buy 5 GRAI

Option A — exactly the rule GIVE uses today

The emptied stock vanishes; the new one is appended at the end of the line. Nothing about the existing behaviour changes.

IDNAMEITEMS
*5518Farmhands414 SILV, 4 LEAT, 5 GRAI
hoverwas: 120 SILV, 12 FUR, 4 LEAT
  • One rule for every order that moves items — which is what this bead is for.
  • The line reads like a report line, because that is what it will become next month.
  • The fur is simply gone from the line. A player scanning the column sees no trace of the sale; only the hover says the fur was ever there.

Option B — an emptied stock stays, at zero

The sale is visible in the column itself: 0 FUR says the fur went, rather than leaving a gap the eye slides over.

IDNAMEITEMS
*5518Farmhands414 SILV, 0 FUR, 4 LEAT, 5 GRAI
hoverwas: 120 SILV, 12 FUR, 4 LEAT
  • The disappearance is the thing worth seeing, and this is the only option that shows it in the column.
  • It changes what GIVE does today, which the bead did not ask for — every existing gift row grows a 0 X.
  • A unit that empties several stocks reads as a row of zeroes, crowding out what it does hold in a column that truncates.
  • The line no longer looks like a report line; no report ever prints 0 FUR.

Option C — emptied stocks vanish, new goods sorted in rather than appended

As Option A, except that grain is placed among the existing goods (alphabetically by tag) instead of tacked on the end.

IDNAMEITEMS
*5518Farmhands5 GRAI, 4 LEAT, 414 SILV
hoverwas: 120 SILV, 12 FUR, 4 LEAT
  • Two rows of the same goods always read in the same order, whatever each unit did this month.
  • Reorders the whole line, so a row can go italic with no number having changed — and the "was:" hover no longer lines up with it left to right.
  • Diverges from the report's own ordering, which the column otherwise mirrors exactly.
  • Changes GIVE's shipped behaviour, as Option B does.
