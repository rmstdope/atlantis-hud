the question the case with no catalogue at all

With a catalogue loaded, both cases already say everything they can. Without one — the transient state while a game’s ruleset is still arriving, or a build that failed to fetch it — case 2 says nothing: unknown-item is skipped outright when there is no catalogue to check a word against, by design. So a GIVE 1 50 SPCIES silently leaves a + ? on the row and no sentence anywhere.

Does that earn an advisory of its own? An advisory is a new code and a new Settings row, which is yours to approve. The two answers differ in exactly what the Problems panel says on a rulesetless report. The navigator chose A.

Without a catalogue the application already goes quiet everywhere else — no magic tree, no game-data lookups, no item links — and it says so nowhere. This keeps that habit. The + ? on the row is still the mark that something on this line could not be counted.

Costs: on a rulesetless report a mistyped item name is invisible except for the + ?.

A GIVE this report cannot identify Warn when a GIVE names goods that cannot be identified at all.

Fires only where nothing else does — a GIVE whose goods resolve to nothing and no catalogue to blame it on. With a catalogue loaded this row never produces a line, because unknown-item gets there first.

Costs: a code, a settings row and a string that exist for one transient state; a player who never loses their catalogue never sees it.

rejected widen unknown-item to fire without a catalogue

The obvious third answer — drop the “only when we have a catalogue” gate on the existing warning — floods the panel: with no catalogue every item word in every order is unrecognised, so a fifty-line order file grows fifty warnings that all say the same thing. Not offered.
