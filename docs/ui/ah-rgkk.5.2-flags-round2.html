A word the report printed that the eleven do not cover appears only when the unit actually carries it, below the rule, in the report’s own words.
  • under strength is dropped from the list and kept as a passenger. No rule defines it and no fixture contains it, so the popup never claims it is off — but if a report prints it, or any other word a future server invents, it gets a line at the bottom saying it is on. Losing a line must never lose a fact.
  • A flag cleared by the other order names that order. rules/guard and rules/avoid: “The Guard and Avoid Combat flags are mutually exclusive; setting one automatically cancels the other”, so an AVOID 1 that clears guard says AVOID 1 on both lines rather than inventing a GUARD 0 you never wrote.
  • The cause is the order as you would type it — GUARD 1, BEHIND 0 — not prose such as your guard order.
  • Line order: the flags this month changed first, then the rest, separated by a hairline, each block in the Flags column’s own letter order (A B G H N X R S T C F), with battle spoils and any passenger last. Same shape as every other popup in the family: this month first, then the rest.
  • A flag is named in the report’s own words where it printed one, and the game’s two spellings for one flag (on guard/guarding, taxing/autotax, no aid/receiving no aid) draw one line, not two.
  • An off is dimmed, the same ink the notes use, so eleven lines read as three or four facts against a background.
  • A foreign unit gets exactly the same popup, every line unchanged: none of your orders can move another faction’s flags.

Unchanged: GUARD 0 and AVOID 1 currently fail to clear a guard flag the report printed, because the core matches the order’s word guarding against the report’s word on guard. That is a defect in the Rust core; this popup will keep agreeing with the cell it explains, and I am filing the defect as a separate bug bead for you to rank.
