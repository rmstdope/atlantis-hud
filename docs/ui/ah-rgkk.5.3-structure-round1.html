ah-rgkk.5.3 — the Structure popup, round 1

What is settled and not being re-opened. The popup itself, its heading and its cap (ah-rgkk.1); the family’s before → after pair (ah-rgkk.6, R1); and ah-rgkk.5.2’s V1 — a changed value draws the pair with the order that did it as a dim trailing clause.

What is new here. Today the Structure popup shows one line — structure valued the full label — and its “why” is the report’s raw structure number: a unit that moved from a longship into a fort reads was: 329, and one that walked out reads was: —. This bead names both sides the way the cell names them and says which order did it.

Why the order can be named at all, and exactly. rules/enter: “Attempt to enter the specified object. If issued from inside another object, the unit will first leave the object it is currently in.” rules/leave: “Leave the object you are currently in.” The preview changes a unit’s structure from those two orders and nothing else (effects.rs, board), so the before/after pair determines the order with no guesswork: a structure after means ENTER <that number> — a move between two needs no LEAVE, per the rule above — and nothing after means LEAVE. No line number is recorded, so the popup can name the order but never the line it sits on.

Two questions: Q1 and Q2. Q1 is the one that matters, and it sets a precedent for every long value in this table.

The scene. Braves (1487) was found by the report inside Wavecrest [329] · Longship. This month you write ENTER 12, and Odds and Ends [12] · Fort is where it ends up. The Structure cell reads Odds and Ends [12] · Fort.

Q1 — a pair of two long names does not fit on one line

Every other column’s pair is two short figures (8 → 12, on → off). A structure label is about 25 characters, so two of them and an arrow is wider than the popup has ever been. The popup is 384px at its widest — the frames below are drawn at that width, so what you see is what wraps.
