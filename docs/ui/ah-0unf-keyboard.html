Option A — nothing selected until you press a key

The tree opens exactly as it does today: no row is marked. The arrow keys work straight away — no need to Tab into the list first. The first ↓ marks the top skill; the first ↑ marks the last one. If the tree was opened on a particular skill (from the command palette, or by following a +chip) that skill is already marked, and the arrows carry on from it.

Option B — Up and Down, plus jumps between branches

Everything in Option A, and four more keys: Page Down jumps to the first skill of the next branch, Page Up to the first skill of this branch (or the previous one if already there); Home and End go to the very first and very last skill. Cost: four keys to learn and list in the shortcut help — but none of them is needed to reach anything.

Option A — the marked skill is the tree's current skill

Marking a skill with the keys is the same thing as the light the tree already has (the one following a +chip gives): soft blue fill, plus a blue ring while the keys are in use. So the two never disagree, and switching to Whole graph opens it centred on the skill you had marked — and switching back lands on it again.

Option A — Tab keeps working as it does today

Tab still stops on every skill name and every +chip, in order, exactly as now. The arrows are an addition: wherever Tab has put you, ↓ carries on from that skill. And wherever the arrows have put you, Tab moves on to that row's +chips, then to the next skill. The mark always sits on the skill the keyboard is on. Cost: getting past the list with Tab alone still takes many presses — but that is no worse than today.
