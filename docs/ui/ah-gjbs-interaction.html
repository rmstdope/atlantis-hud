Magic study tree — interaction, and the rule that matters most

Settled so far: branch cards with a Whole graph toggle, static (no faction overlay yet), MANI set apart, opened by F3, the palette and a mage's skill; the view choice is remembered for the session; the graph pans and zooms on a narrow window; and the wording is the plain set.

Four things are still open, and each one is a place an implementer would otherwise have to guess.

2 · What a row does when clicked

The dictionary already holds every skill's full description and levels. The tree could hand off to it.

A skill name opens that skill in the dictionary. A violet chip jumps to that skill's own row in the tree.

3 · The cap rule

rules/magic_skills: a magic skill can never rise above the skills it depends on. If a mage wants summon lich at 3 he needs raise undead at 3, which needs summon skeletons at 3. It is the single most useful thing the tree knows, and the branch cards do not say it anywhere.

3AOne line per card

A footnote at the foot of every card, in the same words each time.
