ah-t2pn.4 — the warning that goes with the corrected column

You chose one code, region-pool-oversubscribed, one finding per contending unit on its own order line, wording mirroring the shipped claims-exceed-unclaimed (“your units claim {total} between them and the faction has {purse}”).

One code now has to carry five sentences, because the pools are measured in different things — and ah-t2pn.3's decision has created a case the family interview never saw.

Silver pools say has / pays; markets say wants / has and are named in goods, because that is what the market line prints. All five keep claims-exceed-unclaimed's spine: your units … between them and …

The new case one unit, no contention

ah-t2pn.3 settles markets whenever anyone trades, not only when two units contend — that is what caps a lone unit ordering BUY 200 where 100 exist. So the pool is oversubscribed by one unit, on its own.

Market has 100 horses.   One unit orders BUY 200 HORS.   Nobody else is trading.

 What happens
A — a second sentence for the lone case this unit buys 200 horses and this market has 100
Reads correctly, and the plural sentence is kept for the genuine contention it was written for. Costs a sixth and seventh string (buying and selling).
B — the finding fires only with two or more units The lone over-buyer is still capped in the column (that was your decision in ah-t2pn.3) but raises no finding. One sentence per pool, and the warning stays about contention, which is what the code is named for. The lone case is then silently corrected with nothing saying why.
C — keep the plural sentence for one unit No new string. Reads wrong on the commonest single-unit mistake there is.
