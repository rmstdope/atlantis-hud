Harness scripts — that live in the wrong repository

Two pieces of the harness are cerebro's job but live in this project's scripts/, and are reached through this project's package manager. Another project adopting the fleet gets an agent instruction that cannot run.

# agents/orchestrator.md pnpm sightings # -> tsx scripts/retroSightings.ts, in ATLANTIS-HUD # skills/implement-bead/SKILL.md:363 pnpm exec tsx scripts/diskPreflight.ts # also this project's

Both are genuinely cerebro concepts. Retrospectives are the fleet's own practice — the conf already declares retro_dir  docs/retrospectives — and the disk floor is what stops an implementer starting a bead it cannot build.

Worse, cerebro already reaches back into this project to read the floor: prune-worktrees.sh seds FREE_SPACE_FLOOR_GB out of scripts/diskPreflight.ts, because a threshold of its own would drift from the one that refuses to start beads. A shared submodule grepping a consumer's TypeScript for a number is the coupling in its clearest form.

1 · retroSightings.ts — 500 lines of TypeScript in a bash-and-elisp repo

It reads the retrospectives, treats their Seen before citations as a graph, and reports each connected component as one finding. It imports nothing but node: builtins — no npm packages at all — which is what makes the second option below possible.

AMove it as TypeScript

The file moves to .claude/cerebro/scripts/retroSightings.ts and is called by path. cerebro now carries a TypeScript file and needs a TypeScript runner.
$ pnpm exec tsx \
    .claude/cerebro/scripts/retroSightings.ts
Repeated findings (3+ sightings)
  11 disk floor refuses the build

a consumer with no tsx:
command not found: tsx
  • The code moves unchanged — no rewrite, no risk to a working algorithm
  • cerebro gains a TypeScript dependency it has never had
  • A consumer that is not a Node project cannot run it at all

BMove it as plain JavaScript

The types come off and it becomes .claude/cerebro/scripts/retro-sightings.mjs, run by node directly. It uses no npm packages, so nothing else has to come with it.
$ node \
    .claude/cerebro/scripts/retro-sightings.mjs
Repeated findings (3+ sightings)
  11 disk floor refuses the build

a consumer with node:
works, with nothing installed
  • Needs only node — no package manager, no install, no tsx
  • Works in a consumer that is not a JavaScript project at all
  • A rewrite of working code, and its type-checking goes with the types
  • Its unit tests are Vitest, in this project — they would have to move or go

CLeave it, and declare it

The script stays where its toolchain is. A sightings_cmd project key names how to run it, exactly as release_cmd does — absent means the fleet has no sightings report.
release_cmd pnpm run release
sightings_cmd pnpm sightings
a consumer that has none:
no sightings_cmd - nothing to run,
and nothing said about it
  • No rewrite, no move, and the same pattern as every other project fact
  • A consumer may point it at their own implementation in any language
  • The fleet's own practice stays outside the fleet's own repository
  • Every consumer that wants it has to write it themselves

2 · The disk preflight, and the floor two scripts share

This is what an implementer prints when it will not start, and it is the message you read when a bead stalls.

icerebro owns the check; the project declares the floor

A .claude/cerebro/scripts/disk-preflight in bash. The number becomes a project key, so prune-worktrees.sh and the preflight read the same declaration instead of one grepping the other's source.
disk_floor_gb 8
$ .claude/cerebro/scripts/disk-preflight
disk: 4.7 GB free, below the 8 GB
floor needed to build.
reclaimable: 2.1 GB in ~/.cargo/…
exit 1 - do not start
  • Kills the grep-a-consumer's-TypeScript-for-a-number coupling outright
  • Every consumer gets the check that eleven retrospectives say is needed
  • One declared number, read by both, cannot drift
  • A rewrite in bash of a tested TypeScript file, and the app's own test of it goes

iiAn optional hook the project supplies

A preflight_cmd key. If it names something, run it and do not start on a non-zero exit. If it names nothing, there is no preflight and that is fine.
preflight_cmd pnpm exec tsx scripts/diskPreflight.ts
$ (what preflight_cmd names)
disk: 4.7 GB free, below the 8 GB
floor needed to build.

a consumer with no hook:
nothing runs, the bead starts
  • Nothing is rewritten; this project keeps the file and the test it already has
  • A consumer may check anything it likes, not only disk
  • A consumer gets no disk check unless they write one — the commonest stall in this repository's history, unguarded by default
  • Leaves prune-worktrees.sh still grepping a TypeScript file for the floor
