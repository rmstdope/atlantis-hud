Linking a fleet's manifest — proposals (bead ah-t5fk)

Your words: “When clicking on a fleet, the game data dialog comes up, but the search shown there is for the fleet summary, e.g. ‘Galley, 40 Galleons, 11 Galleys, 10 Balloons’. There should be different links for Galleons, Galleys and Balloons.”

§1  Today

Structures
Frozen Tomb [194] : Galley, 40 Galleons, 11 Galleys, 10 Balloons
The whole manifest is one link, asking the dictionary for a building called Galley, 40 Galleons, 11 Galleys, 10 Balloons. Four real entries were named and you get a dead end. Two things are wrong: the span, and the lookup — buildingEntryId() searches buildings, but every vessel is a ship entry.
All nine vessel types are in the catalogue, singular, with tags: Longship LONG, Raft RAFT, Cog COG, Galleon GALL, Galley GLLY, Corsair CORS, Balloon BALL, Airship AIRS, Cloudship CLOU. So every name in a manifest has somewhere real to go.

§2  What gets linked

A The vessel names only

Frozen Tomb [194] : Galley, 40 Galleons, 11 Galleys, 10 Balloons
  • The link text is the thing the link opens. Clicking Galleons opens Galleon; the count is yours, not the catalogue's.
  • Counts stay plain, so the numbers still read as a tally rather than as navigation.
  • Small targets — four short words in a row, each its own link.

B Count and name together

Frozen Tomb [194] : Galley, 40 Galleons, 11 Galleys, 10 Balloons
  • Bigger click targets, and each segment is one obvious unit.
  • The link text no longer matches what opens. Clicking 40 Galleons opens a page about one Galleon, which reads as a promise not kept.

§3  The leading word vesselCount drops it with .slice(1), on purpose

In Galley, 40 Galleons, 11 Galleys, 10 Balloons the first segment is the structure's own vessel kind — what the fleet is displayed as — not a counted entry. ah-3pr9 established that it is a label rather than a vessel: Cloudship, 14 Cloudships… totals 14, not 15.

C Link it, like any other vessel name

Frozen Tomb [194] : Galley, 40 Galleons, …
  • It is a vessel name, and it has a real catalogue entry.
  • Consistent: every vessel word in the line behaves the same way.
  • It is not part of the tally, so linking it may imply it is one more Galley.

D Leave it plain

Frozen Tomb [194] : Galley, 40 Galleons, 11 Galleys, 10 Balloons
  • Only the manifest is navigable; the label reads as a heading.
  • The one word a player is most likely to click — the fleet's own kind — is the one that does nothing.
  • A single-vessel structure (Ship [623] : Galley) would then have no link at all, losing behaviour it has today.

A plain trailing-S strip covers every vessel in the fixtures — but the repository already has a better-tested rule for exactly this: isKeyword (orderCase.ts:33) tries the word as written first, then without ES, then without S, mirroring the Rust core's item_spellings. I intend to reuse that rather than write a second rule, so a vessel whose plural is irregular is looked up as written before anything is stripped.

§5  A vessel the catalogue does not describe

ah-5jkt.2 already decided this for structure kinds: an id the index does not hold still opens the dialog and says the entry is absent — “saying so is the whole point of landing there” (gameDataDialogState.ts:66-69). I propose the same here rather than silently dropping the link, so a manifest never has some words navigable and others not for reasons the player cannot see. Say if you would rather an unknown vessel stayed plain text.
