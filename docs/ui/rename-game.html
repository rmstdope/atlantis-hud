No mode: the name is an input at all times, saved on Enter or when focus leaves it, reverted on Esc. Fewest clicks; the cost is that a click meant to select text saves nothing and a stray edit is committed on blur, with no Cancel to press — and an empty name has to be reverted silently rather than refused, since there is no Save to refuse.

What was decided (2026-08-16)

A was chosen over B (a button in the stack) and C (an always-editable field). The words: the link “Rename”, buttons “Save” / “Cancel” (“Saving…” and disabled while the core writes), the empty-name line “a game needs a name” (the same words creation uses; refused, field stays open), the duplicate line “Another game is already called “<name>”.” as an amber warning while typing that never blocks Save. Enter saves, Esc cancels the edit only (a second Esc closes the picker); focus lands in the field with the text selected and returns to Rename after Save or Cancel. A name unchanged after trimming just closes the field. A refusal from the core shows in the picker's existing error line at the bottom, with the field left open. The name is trimmed and saved into the game's manifest, so the header chip, the Games row, the Settings dialog and later backup file names follow; files already written keep the old name.
