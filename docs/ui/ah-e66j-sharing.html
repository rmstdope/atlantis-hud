ah-e66j — a faction-mate's silver pays upkeep, SHARE flag or no SHARE flag

The rules make maintenance sharing automatic and separate from the SHARE flag:

“Money will be shared automatically between your units in the same region, if one is starving and another has more than enough … this sharing of money applies only for maintenance costs, and does not occur for other purposes.”

This is step 4 of the maintenance payment order — silver from other faction units in the same region — sitting between a unit's own silver (step 3) and its own food (step 5). The application pools only when somebody in the hex sets SHARE, so a unit is warned it cannot pay its upkeep while a faction-mate beside it sits on a thousand silver.

Removing that false warning is not in question. Three consequences are, and each has a precedent that points a different way.

Question 1 what the hover says when nobody set SHARE

Today the note is inferred, not stated: when a unit's own figure is negative and no warning names it, the hover says — regardless of why —

“Shared silver in this hex covers the shortfall.”

So this sentence starts appearing on its own the moment the bug is fixed, in hexes where the player set no SHARE flag anywhere and shared nothing deliberately.

OptionThe sentence
A — one sentence, reworded “Another unit in this hex covers the shortfall.” True whether the sharing was automatic or flagged. One string, and it stops claiming the player did something they did not.
B — two sentences flagged: “Shared silver in this hex covers the shortfall.”
automatic: “A faction-mate's silver in this hex pays this unit's upkeep.”		 Says which rule saved it, and the automatic one names upkeep — which is the only thing automatic sharing ever pays for. Needs the core to say which, so a new field.
C — leave it “Shared silver in this hex covers the shortfall.” everywhere. No work. Tells a player who set no flag that their silver was shared.

Question 3 when the hex cannot cover everybody

Four units owe 200 between them; the hex holds 120 spare. Which unit goes without cannot be told. The two neighbouring beads answered this differently, so there is no default to inherit.
