What a mature turn changed

Redrawing on turn 71 rather than turn 2 exposed problems the small report could not.

Hex orientation was wrong

  • Atlantis exits are N, S, NE, SE, NW, SW — a direct northern neighbour means flat-top hexes.
  • All four earlier mockups drew pointy-top. The mapping is px = x·1.5R, py = y·(√3R/2), with only x+y even valid.
  • packages/shared/src/PixiHexMap.tsx has the same bug today, and mapData.ts parses "A1" style ids that this ruleset never emits.

Four map states

  • Current — in this report. 11 regions.
  • Previously visited — full data from an earlier turn, absent now, so possibly wrong. Hatched and age-faded; the Staleness layer toggles it.
  • Known by name — 45 regions named in an Exits block; terrain and province only.
  • Unexplored — everything else, not selectable.
  • This makes region records turn-versioned: persistence must keep per-region last-seen turn, not just the latest import.

The table needs virtualising

  • Inholm holds 92 units across 24 structures. The dock shows 21; the rest scroll.
  • Units nest inside structures, so the table is really a flattened tree — the Structure column carries that nesting.
  • Sorting own-units-first matters when one of 63 is yours.

Panels need summarise-then-expand

  • 24 structures and 9 wanted goods overflow a 306px panel. Counts in the section headers and a + 18 more affordance handle it.
  • Item lists on big units run to twenty entries; the table truncates with an ellipsis and the unit panel ranks by quantity.
Fixture value. Worth committing alongside the turn 2 file as tests/fixtures/reports/neworigins-3.0.0-f95-t71.rep. At 4,028 lines it exercises battles, ship and building structures with nested units, 63-unit regions, wrapped continuation lines everywhere, declared attitudes, skill reports, and an orders template with 27 unit blocks. The small turn 2 report stays useful as the fast parser test; this one is the realistic one.
