Finding historical entries in the palette

Chosen: A. The same search for “Windward” finds a ship that appeared in an earlier report but not the latest one. A historical result says when it was last seen before it is opened, while preserving the existing result shape and taking the player to its last-known hex.

How should a historical match identify itself?

A — recommended Say when it was last seen

An amber, compact “last seen turn 42” appears before the existing kind. It makes the result useful without promising it is current.

B Keep historical matches visually ordinary

The item appears with the same name and kind as any current match. Its age is only discovered after selecting it.

  • The last-known hex is less clearly a historical destination.

What happens after selection?

Both choices: selecting a historical unit, building, ship, or other named object closes the palette and selects its last-known hex. The normal region view remains responsible for showing that the hex is historical. Nothing is changed or written by searching or by selecting a result.

States and keyboard behaviour

SituationWhat the player sees or does
Search has current and historical matchesThey share one list and use the existing relevance order. Historical matches carry the chosen identification; current matches do not.
Only historical matches existThey appear normally with the chosen identification; there is no separate empty state or warning.
No matchesThe existing “nothing matches” line remains unchanged.
Long name or a narrow windowThe name shortens with an ellipsis; the historical label and kind stay visible at the right. The dialog otherwise keeps its existing responsive, scrollable list.
KeyboardThe input receives focus when opened. Arrow keys and Enter work as they do today. Esc or clicking outside closes it and restores focus to what opened it; selecting a result deliberately moves attention to the selected hex.
Reload, report switch, or new reportNo query or selection is saved. The next palette reflects the historical entries available in the data then loaded; an entry becomes current again if it reappears in a newer report.
