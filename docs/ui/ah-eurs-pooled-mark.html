ah-eurs — the pointer’s wording — round 2

In hex (36,4) three units carry sharing, so horses pool and the shortfall is judged against the pool. The finding is hex-anchored — unitId and line are both null — so orderLint.ts:31 drops it and the order line carries no mark. You went looking for it, did not find it, and read it as a regression.

ah-sdda already settled that the finding is right. The pool genuinely is not that one line’s fault. This is only about telling the reader, where they are typing, that something is being reported elsewhere.

One fact that decides how far we can go: the contributing line is knowable. ledger.charged_at[(unit, tag)] already holds the PlacedIntent — line and columns — and the per-unit shortfall path already uses exactly that to anchor its own finding. Nothing new has to be computed; the pooled path simply throws it away today. Shapes A and B below are therefore both buildable.

SETTLED Round 1

  • A — a pointer on the line, not the finding itself. The pooled finding stays hex-anchored as it is.
  • Every contributing line gets the mark, not just the largest or the first.
  • A sharer’s line is not marked — its stock is inside the pool, so it claims nothing against it.

3 · What “Problems” does, and what if it is switched off

The region panel’s Problems section has a toggle the player can turn off; the chip keeps the count. A pointer to a section that is closed is a dead end.

P1 Plain words, no link

mountain (36,4)Problems 1
warningThis hex is short of horses between its units. See Problems for the hex.
  • Nothing to build, nothing to keep working.
  • If Problems is toggled off, the reader is sent somewhere that shows nothing.
