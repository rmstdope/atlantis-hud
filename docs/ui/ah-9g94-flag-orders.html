Question 1 — REVEAL UNIT

rules/reveal gives three states: REVEAL UNIT shows the unit, REVEAL FACTION shows it and its faction, bare REVEAL cancels both. But every committed report only ever prints revealing faction; no report in this repository shows a word for a unit revealing only itself, and ah-rgkk.5.2 deliberately left it out ("a twelfth setting… nothing for a line to say"). So there is no report word to copy. Orders shown: REVEAL UNIT on a unit whose report printed nothing about revealing.

Question 2 — what SPOILS ALL shows

rules/spoils: "SPOILS ALL will allow a unit to collect any spoils which are dropped regardless of weight or capacity", and bare SPOILS "is equivalent to 'SPOILS ALL'". No report fixture prints a flag for it, so SPOILS ALL in the preview means clearing whatever spoils flag the report had. ah-rgkk.5.2 named the no-flag state not shown — deliberately an admission, not a claimed default. That reads oddly when the player has just ordered it. Orders: SPOILS ALL on a unit whose report printed riding battle spoils.

Question 3 — the silver forecast

Not a drawing question. silver.rs's taxes() and is_consuming() already read the previewed flags, not the report's (semantics.rs:1550, 4726). So the moment AUTOTAX is wired, writing AUTOTAX 1 will also credit the unit a month of tax income, enter it into the region's tax contention against every other taxer, stop it counting as idle (unit-does-nothing), and raise the "taxing a pillaged hex" and "taxing a guarded hex" findings. CONSUME UNIT/FACTION will start paying maintenance in food rather than silver. That is what happens for free; the alternative is extra code to hold the money still while the flag moves.
