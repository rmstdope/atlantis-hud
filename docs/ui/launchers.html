Starting an agent — the seven shims

Every role has a one-line script that starts it: run-planner, run-orchestrator, run-psylocke and four more. Each does nothing but exec launch <Name>, and each says in its own comment that it exists "because the docs and the navigator's fingers know it". Seven copies of one line.

That is a real reason and it is your reason — these are the commands you type, and they are what CLAUDE.md documents. So the question is not whether the duplication is ugly, it is whether you want the commands to change.

There is a second, smaller thing tangled in it: the shims are not named consistently. Four are named after the agent, three after the role, and one role has two agents.

1 · What replaces seven hand-written copies

AOne dispatcher, symlinked

One real script; the seven names become symlinks to it, and it reads which agent to start from the name it was invoked as. Every command you know keeps working, byte for byte.
$ ls -l scripts/run-*
run-beast   -> run-agent
run-cypher  -> run-agent
run-forge   -> run-agent
... and four more

$ scripts/run-planner
starting Xavier ...

a consumer adds a role:
$ ln -s run-agent run-archivist
  • Nothing you type changes, and nothing in CLAUDE.md changes
  • One file to fix when launching changes, not seven
  • A consumer adds a shim with one ln -s
  • Symlinks in git are a thing some checkouts and some Windows setups mishandle
  • Argv-name dispatch is a clever trick, and clever is a cost

BGenerated from the roster

A script writes the shims from scripts/roster, and a test fails if the checked-in files disagree with what it would write. Real files, no symlinks.
$ scripts/generate-launchers
wrote 8 shims from the roster

$ scripts/run-planner
starting Xavier ...

a consumer adds a role, then:
$ scripts/generate-launchers
wrote 9 shims from the roster
  + run-archivist
  • Nothing you type changes
  • Ordinary files — no symlink, nothing clever to explain
  • A generator, a check, and generated files in the tree: three new things
  • The duplication still exists, it is just now nobody's fault

CDrop them — launch <Name> only

The seven go. One command starts any agent, by name, and the docs say so. launch already does all the work and is already documented for the planners.
$ scripts/launch Xavier
starting Xavier ...
$ scripts/launch Cyclops
starting Cyclops ...

$ scripts/run-planner
zsh: no such file or directory

$ scripts/launch
usage: launch <name>
Xavier Beast Cerebro Moira
Psylocke Cypher Forge
Cyclops Storm Wolverine ...
  • One command for everything, and the inconsistency in the table above simply vanishes
  • Least code of the three, and a consumer adds a role by adding a roster line
  • Every command you know stops working, and CLAUDE.md changes in eight places
  • Loses run-implementer's guard against starting Forge as an implementer

2 · The naming inconsistency

Only worth deciding if the shims stay. run-planner starts Xavier and not Beast, which is the one that actually misleads.

iLeave it

The names are what they are; each shim's comment already explains itself. Nothing you type changes.
$ run-planner   Xavier
$ run-beast     Beast
$ run-forge     Forge
  • Zero disruption
  • run-planner will keep reading as "start a planner"

iiEverything by agent name

One rule: the shim is named after the agent it starts. run-xavier, run-cerebro, run-moira. The role-named ones keep working as aliases.
$ run-xavier    Xavier
$ run-beast     Beast
$ run-cerebro   Cerebro
$ run-moira     Moira
old names still work
  • One rule with no exceptions, and the two planners finally look alike
  • Nothing breaks — the old names stay as aliases
  • More names, not fewer, which is the opposite of the bead's direction

iiiRetire run-planner only

Add run-xavier, and make run-planner print which planner it is starting and that it means Xavier. The other six are left alone.
$ run-planner
run-planner starts Xavier;
Beast is run-beast
starting Xavier ...
  • Fixes the one name that actually misleads, and nothing else
  • Smallest change that removes a real trap
  • A notice on every start is noise once you have read it twice
