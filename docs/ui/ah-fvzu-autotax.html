ah-fvzu — a unit that taxes by flag, not by order

The AUTOTAX order sets a unit's taxing flag, and it then taxes every turn without a TAX line in that turn's orders. The forecast prices only the explicit Intent::Tax, so a flagged unit is shown earning nothing.

The corpus has one such unit of ours, and it is not a small one:

* City Guards (13303), on guard, The Disinherited Knights (42), revealing faction, holding, taxing, sharing, 800 orcs [ORC], 2 catapults [CATP], 2049 swords [SWOR]…

800 men taxing is $40,000 before the region's cap. The column shows 0.

The arithmetic, the tax-base cap, the pillage conflict and the several-taxers split are all settled already — a flagged taxer simply joins them, exactly as an explicit one does. What is not settled is that this unit has no order at all, so there is nothing on the page to explain where the money came from.

Question 1 where does the money appear to come from?

Every other income in the column is answered by a line in the orders. This one is answered by a flag on the unit, set in some earlier turn and invisible in this turn's orders.

OptionThe hover
A — say it “This unit is set to tax every turn, so it taxes without an order.” Answers the question a reader will actually have — why is this unit earning $40,000 when its orders are empty? One more sentence in a hover that has several.
B — say nothing The Income figure alone, like every other unit. Consistent, and cheapest. A player who did not set the flag themselves — or set it twenty turns ago — has no way to find out from this screen.

Question 2 is a flagged unit “doing nothing”?

City Guards has no orders at all. So today it also carries this mark:

has no order that spends the month  — the unit-does-nothing advisory

Which is false: it spends the month taxing, and it is meant to. There is no order the player could add to satisfy the advice — adding TAX would be redundant.

Option
Exempt it, in this bead A flagged unit spends its month, so the mark does not fire. The two defects are the same unit on the same screen, and a player who fixes one still sees the other. Small: one condition beside the two exemptions check_idle_units already has.
Leave it, file it separately The mark keeps firing until its own bead. Keeps this bead to the silver column, which is what its title says. The false mark stays on the one unit in the corpus it affects.

Question 3 the flag and an explicit TAX together

A unit may carry the flag and be given a TAX order this turn. It still taxes once.

Option
Count once, silently Income is the same either way. The redundant TAX is harmless and unmentioned.
Count once, and say so A mark on the redundant TAX line: “this unit already taxes every turn”. Catches a player who does not know the flag is set — and needs a new advisory code, its own toggle and its own row.
