Order OCD — when it fires, and how far it reaches (bead ah-bn6)

Orders are case-insensitive to the engine, so this is pure taste: some players want MOVE, STUDY and ALL shouting so the commands separate from the names. The one hard rule is that nothing inside quotation marks is ever touched — a unit called “Seven of Eight” is data, not presentation. Text after a ; comment is left alone for the same reason.

Decided, 2026-08-17, over two rounds. It fires as the word ends (T1) — the space after a word flips it, never mid-word. It reaches every word the rules know (R2, K3): the grammar's own words, the item tags, and the item and skill names, so only numbers, unit ids, quoted names and comments survive in lower case. Orders already written are tidied the first time you open that unit with the setting on (E3). The setting's wording is the bead's own sentence, shipped as suggested. The work is split in two: the core must publish the vocabulary before the editor can use it.

In every strip below the player is typing the same three lines in lower case. Brass is what the setting changed; green is a quoted name, which never changes.

1. When does it fire? the decision the whole feel of the feature rests on

T1 As the word ends

The moment you type the space after a command, it goes uppercase under your hands. Never mid-word — the word is only touched once you have finished it.

typing
1move
press space
1MOVE
carry on
1MOVE n nw
  • You see it work, so you trust it
  • Nothing to remember and nothing to press
  • Text changing under the caret is the classic way an editor feels possessed
  • Undo has to put back what you typed, not what it made — one Ctrl+Z, not two

T2 When you leave the line

The line you are on is left exactly as typed. It is tidied the moment the caret moves to another line — on Enter, on an arrow, on a click elsewhere.

typing
1move n nw
press enter
1MOVE n nw
2
next line
1MOVE n nw
2study combat
  • Nothing ever changes at the caret, so typing feels ordinary
  • A whole line at once is one clean undo step
  • The line you are looking at is the one that looks wrong
  • The last line you typed stays lower case until you go somewhere else

T3 When the unit's orders are put away

Type as you like; the whole block is tidied when you select another unit or the draft is saved — the same moment the editor already tidies a trailing newline.

typing
1move n nw
2study combat
still lower
1move n nw
2study combat
pick another unit, come back
1MOVE n nw
2STUDY combat
  • Typing is never interrupted in any way
  • Reuses the moment the editor already rewrites text on its own
  • You do not see it happen, so the first time it looks like a bug
  • A player who never leaves the unit never sees it work

T4 Only when asked

Not a live setting at all but a command — Tidy the orders in the command palette — that uppercases the current unit's orders when you run it.

typing
1move n nw
2study combat
palette
> tidy the orders
run it
1MOVE n nw
2STUDY combat
  • Nothing can ever surprise you; it happens because you asked
  • It is no longer the setting the bead asked for
  • Tedious in exactly the way the bead complains about — you must remember, every unit

2. How far does it reach? the same three lines, both ways

R1 Commands only

The words the core already publishes as order_commands — the first word of a line. Everything after it is left as typed.

1MOVE n nw
2GIVE 2042 all silv
3NAME unit "Seven of Eight"
4STUDY combat ; cheaper here
  • The keyword list already exists and is already in the app — nothing new to fetch
  • The command position is unambiguous: the first word, after an optional @
  • all and silv stay lower, which is arguably half the job

R2 Commands and argument keywords

Also ALL, SILV, UNIT, directions, item classes — every fixed word the grammar knows, as against a name or a number.

1MOVE N NW
2GIVE 2042 ALL SILV
3NAME UNIT "Seven of Eight"
4STUDY COMBAT ; cheaper here
  • Reads like the manual, which is what the setting's name promises
  • The core publishes only the command names to the app today — the argument keywords are known to Rust alone, so this needs a new call across the boundary
  • A skill name like combat is a keyword to the grammar; uppercasing it is a judgement, not a fact

2b. R2 was chosen — but which words is “a keyword”? the same four lines, three readings

K1 Words the grammar fixes

Only words written into the order grammar itself: ALL, UNIT, FACTION, the directions, the item classes. Item and skill names come from the ruleset, not the grammar, and stay as typed.

1MOVE N NW
2GIVE 2042 ALL silv
3NAME UNIT "Seven of Eight"
4STUDY combat
  • One fixed list, the same in every game — nothing depends on which ruleset is open
  • silv stays lower, and it is the word players type most

K2 Grammar words and item tags

The above, plus the short item tags the ruleset defines — SILV, SWOR, HORS. Skill names and full item names stay as typed.

1MOVE N NW
2GIVE 2042 ALL SILV
3NAME UNIT "Seven of Eight"
4STUDY combat
  • Matches how the reports themselves write items — tags in capitals
  • Covers the line the bead's own wording promises
  • The list now depends on the open ruleset, so it must be fetched per game rather than once

K3 Every word the rules know

Also skill names and full item names: COMBAT, LONGBOW, TACTICS. Only numbers, unit ids and quoted names are left.

1MOVE N NW
2GIVE 2042 ALL SILV
3NAME UNIT "Seven of Eight"
4STUDY COMBAT
  • Nothing is left half-shouted; the strongest reading of “OCD”
  • A skill name can be two words (unit tactics) and a plain word like wood is both an item and ordinary English — more chances to shout at something that was not a keyword

3. What about the orders already written? the moment the setting is switched on

E1 Leave them; only new typing is tidied

Switching the setting on changes nothing that already exists. A turn half-written in lower case stays mixed until each line is touched.

  • Nothing is rewritten behind the player's back, ever
  • A mixed-case turn is exactly what the OCD player cannot bear

E2 Tidy everything, at once, on switching on

Turning it on uppercases every unit's orders in the whole turn immediately.

  • The turn is consistent from the moment it is on, which is the point of the setting
  • One click silently rewrites the whole document — and there is no undo across units

E3 Tidy each unit's orders when you next open them

Nothing happens on the click. A unit's block is uppercased the first time you select that unit with the setting on — the same pass that runs at T1/T2/T3, applied to what is already there.

  • The turn converges on consistency as you work through it
  • Never rewrites anything you are not looking at
  • A unit you never open keeps its lower case into the export

4. The setting itself in the global settings tab — there is no per-game settings store, so it is global by construction

✓
Order OCD
Uppercase the command keywords as you write, so MOVE, STUDY and ALL stand out from names. Text inside quotes is left alone.

The wording above is the bead's own suggestion, drawn as it would ship. It mentions ALL, which only tells the truth if section 2 lands on R2 — if it lands on R1 the sentence needs to lose it.

Decided without asking, and say so if any of it is wrong. Nothing inside "quotes" is ever changed, including a quoted name that contains a keyword; nothing after a ; comment is changed either. The setting is off by default. It lives in the global settings tab, since there is no per-game preference store to put it in. One Ctrl+Z undoes both what you typed and what the setting did to it — never two presses to get one word back.
