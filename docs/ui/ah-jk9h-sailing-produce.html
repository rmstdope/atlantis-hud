ah-jk9h — fishing from a boat that is sailing away

Reported in GitHub issue #679 by a player running real turns. Fishermen and sailors board a boat, the sailors SAIL out to the ocean, the fishermen PRODUCE fish — and the fishermen are flagged as unable to fish where they are.

The HUD checks the region the unit is standing in now. It already works out where the boat is going — that is the dashed arrow — but the order checks cannot see it: the arrow is drawn by a different core call that is given the map, and the checks are not. So this is a choice about what the checks should say when they cannot know the destination.

The reporter's own words for the cost: “a false error on a perfectly legal and quite ordinary fishing-fleet setup, which teaches players to distrust the order errors generally.”

Chosen 2026-08-25 — stay silent for anyone aboard a sailing vessel

The reported case fishermen aboard, sailors sailing to ocean

unit 4102 (Fishermen, aboard Longboat [1801]) PRODUCE fish (no error — this unit is aboard a vessel that is leaving) unit 4103 (Sailors, aboard Longboat [1801]) SAIL S S

The case that must not be lost fishing in a forest, going nowhere

No boat, no SAIL — the error is right and stays on every option.

unit 4200 (Fishermen, in Reprau forest) PRODUCE fish cannot produce fish here: this region produces wood, furs and herbs

The awkward one aboard a sailing boat, producing something no ocean makes

The boat leaves; the unit orders PRODUCE wood. Nowhere it could be going produces wood, so the order is certainly wrong — but the HUD cannot see where it is going.

unit 4104 (Woodsmen, aboard Longboat [1801]) PRODUCE wood (no error — this unit is aboard a vessel that is leaving)

The false error goes, and nothing new has to reach the checks: check_sailing already works out which units are aboard a vessel whose captain has a SAIL order, so this reuses machinery that exists. The cost is the third case - a genuinely impossible PRODUCE goes unwarned whenever the unit is aboard a boat that is leaving.
