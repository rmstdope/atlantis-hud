A FORM number used twice — what the player sees (bead ah-yk7)

The rules: “you should not create two units in the same region in the same month, with the same alias numbers.” The server refuses the second FORM and its whole block, and every later NEW n means the first unit. Today nothing says a word. The check is a semantic one (it needs the report to know which of your units stand in the same hex), so it is a warning like every other check in the panel: never blocking, off-switchable in the Warnings tab.

The two variants below differ in where the warning sits and what it says. The example orders: unit 5 forms NEW 1 twice by copy-paste, and unit 7 in the same hex forms NEW 1 too.

OPTION A One warning per repeat, on the repeat

Every FORM after the first with the same number gets its own warning, underlined on its line, naming where the number was first used. The first FORM is the one that will work and is left alone.

Two warnings, each on the block that will not run. Fixing a line clears its own warning.
  • The underline is on the block that dies — the line the player must edit.
  • Three copies → two warnings; each says which one it clashes with.
  • Nothing marks the first FORM, so a reader starting there sees no hint.

One warning per clashing number, sitting on the first FORM, listing every repeat. The repeats themselves carry no underline.

  • Fewer panel lines when a block was pasted many times.
  • The underline sits on the FORM that is fine; the ones to delete are unmarked.
  • Attributed to unit 5 although unit 7's line is the odd one out.

The states same for both options

Same number, two different units in the hex

Also a mistake per the rules (the alias is per region). The message says which unit already used it — “unit 5 (line 11)” — so it does not read as a copy-paste inside one block. Two units in different hexes may reuse a number freely: no warning.

Inside a TURN block

A FORM inside TURN … ENDTURN is next month's; it is not counted against this month's numbers, and two FORM 1 inside one TURN block are not checked either (next month's checker will).

No report loaded

Semantic checks need the report to know the hexes. With no report there is no warning — the same as every other warning in the panel.
