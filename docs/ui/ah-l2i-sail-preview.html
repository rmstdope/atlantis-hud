ah-l2i — a SAIL order in the units-in-hex table

Today a unit ordered SAIL is drawn leaving on the map and counted as leaving by the order checks, but the units-in-hex table previews it as staying put — the table's reader spells the movement words by hand and was never told about SAIL. This bead gives that reader the one list, so SAIL previews like MOVE does: the row dims and gains a → destination marker, and a copy of the row appears in the destination hex marked ← origin. No new wording, colour or layout — it reuses exactly what MOVE already draws.

The one open question is the passengers. A SAIL order is written on the fleet; the units aboard have no movement order of their own, but they go where the ship goes. Both panes below show the same hex and the same orders — only the passengers differ.

The landing party as it will actually arrive — 28 men, not 6. This is the answer that helps you plan an assault, and it is the one that costs real work: the core must decide who is aboard which fleet and carry each passenger across.

What each costs

A is the one-line change this bead was filed for: the table's reader stops spelling the movement words by hand, so SAIL joins MOVE and ADVANCE, and everything else is already in place. Small, and it removes the divergence.

B is a feature on top: a new rule about who is aboard, every passenger moved, and a question this mockup cannot answer for you — whether a passenger's row should look identical to a unit with its own movement order, or say something different (aboard Wavecrest, say). That is a second bead, not a bigger version of this one.

There is also a middle answer that would make B honest, if you want it eventually: passengers depart, but with their own marker, so the table distinguishes ordered to move from carried.
