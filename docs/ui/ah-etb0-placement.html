Send orders to the server — where the control lives

Three placements for the new Send action. Everything else in the header strip is drawn as it is today: Import, the Export ▾ popover and the settings cog, in that order, inside data-testid="header-actions".

In all three, the control is absent entirely on the web build — the game server sends no CORS headers, so a browser could fire the request but never read the reply, and a Send that cannot report success is worse than no Send. What you are choosing here is only what the desktop shows.

AIts own button

A plain Send button sitting to the right of Export ▾. One click opens the password dialog. This is what the bead as written asks for.
Atlantis HUD Green Tide (4) · turn 71 ⚙
  • Discoverable — a player who has never read a changelog sees it
  • One click to the thing you do every turn
  • A fourth control in a strip that already wraps on a narrow window
  • Sits next to Export but is not an export; the grouping is a small lie
Cost: one more item competing for header width.

A fourth entry in the existing Export ▾ popover, below a divider, so delivery-to-a-file and delivery-to-the-server sit together. The header gains nothing.
