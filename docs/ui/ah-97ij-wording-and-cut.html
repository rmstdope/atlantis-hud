question 1How hard is the obligation?

This is the question the bead actually turns on. A skill that merely exists is reached for when an agent happens to think of it — and the whole problem is that an agent which misremembers a rule does not know it is misremembering, so it never thinks of it. The project’s most repeated retrospective finding, 161 sightings, is a plan asserting an interaction as fact where the fact was false. Here is what replaces CLAUDE.md:8-9 under each option.

AA pointer

The bare URL becomes a pointer to the skill. Nothing is obliged.

CLAUDE.md
### Rules-The rules for the game can be found at https://atlantis-pbem.com/rules+The rules are at https://atlantis-pbem.com/rules and the game data at+https://atlantis-pbem.com/data. Both are committed to this repository and+looked up with `pnpm run atlantis` — see the `atlantis-rules` skill.
  • No new obligation on anybody; nothing to police.
  • Relies on an agent suspecting it is wrong — which is exactly what a misremembered rule prevents.

BA citation rulerecommended

Any Atlantis fact that gets written down must be looked up first, and the lookup named.

  • Turns "I recall" into "I checked", which is the whole point of the bead.
  • Checkable by a reviewer: the lookup is either named or it is not.
  • An obligation on every session, including ones where it is obvious overkill.

CA citation rule, for a named list

Same as B, but obliged only for order syntax, item/skill/structure numbers and the sequence of events.

  • Narrower, so less friction on prose that is only loosely about the game.
  • An agent must first judge whether its claim is on the list — a judgement it makes with the same faulty memory.

question 2When the app disagrees with the game

You asked for the skill to cover config/public/ruleset.json as well as the two pages, because ah-9js fell in that gap. The fork is whether “the data page is the arbiter” is prose an agent reads or a command an agent runs.

AA verify subcommandrecommended

atlantis verify diffs the app’s belief against the committed page and prints every disagreement.

$ pnpm run atlantis verify
comparing config/public/ruleset.json against the committed data page

items      171 / 171 agree
buildings   58 /  58 agree
skills      95 /  96 agree
  MINI  cost   ruleset 10, data page 12

1 disagreement. The data page is the arbiter — regenerate with
pnpm run atlantis refresh, do not edit ruleset.json by hand.

exit 1
  • An agent that suspects a mismatch gets an answer instead of an opinion.
  • It is the check the weekly PR should also run, so one thing serves both.
  • More to build, and it can only compare what the scraper models — items, skills, buildings, movement — not the prose.

BProse in the skill

A short section in SKILL.md naming the file, saying the data page wins, and giving the regenerate command.

  • Costs almost nothing to write and cannot rot into a false pass.
  • An agent still has to notice the disagreement by eye — which is what nobody did in ah-9js.

question 3How this reaches the fleet

It is a P0 with the buffer empty, so how it is cut decides how fast an implementer can start. My reading is that it is two increments, not one: the lookup is useful the day it lands, and the weekly workflow is a different kind of work with different tests. I would split it and let the lookup go first.
