ah-y9hx — a row in a hex-spanning list travels to its hex

The units pane stopped meaning “the units in the selected hex” in ah-1mpx.2: All my units and each Army list units standing in different hexes, and each such list carries a Hex column saying where. Clicking a row selected the unit but left the map where it was, so having found a unit among hundreds there was no way onward to the ground it stands on. The command palette, the turn-messages panel, the problems panel and Alt+↓ all already travel; the units table was the one list that did not.

Chosen behaviour, agreed with the navigator over three rounds. Every scene below is the decision, not an option.

  • A row click in a list that spans hexes — All my units, or any Army — selects the unit and takes the map to its hex.
  • This hex is untouched, mouse and keyboard alike: nothing there ever moves the map.
  • ↑ ↓ still only move the selection. Enter travels; Space does not.
  • Travel follows the unit to another level, and comes back to the unit's hex even when that hex was already selected and the map had been dragged off it.
  • A row whose unit this turn's report does not have still highlights, and the map stays put. Nothing is said about it.

↑ ↓ Home End
move the selection. The map does not move — walking a long list must stay silent.
Enter
travel to the selected unit's hex, in a list that spans hexes. Under This hex it keeps meaning exactly what it means today.
Space
unchanged: selects, and swallows the key so the scroller does not jump.
  • Without this the table has no keyboard route to the hex at all: it is one tab stop per row with a roving tabIndex, so a keyboard player could find a unit and never reach its ground.
  • Space was left alone deliberately — it is also how a reader stops a list scrolling, and a mis-hit must not move the map.
