Decision (2026-08-18): Q1 → A, the late tidy always runs, whatever has been typed meanwhile; Q2 → 2-i, the word the caret is inside is left alone; Q3 → the tidy is not an undo step, as the on-open tidy already is not; Q4 → silent, no notice anywhere; Q5 → turning the setting on while a unit is open tidies it immediately, fixed in the same bead; Q6 → with the editor unfocused there is no caret to protect, so everything is tidied; Q7 → a ruleset switch tidies the open block again against the new catalogue; Q8 → the tidy is a real edit and is saved.

Option B — the tidy standing aside once you had typed — was rejected: it leaves the block you are actually looking at mixed for the rest of the session, which is the complaint this bead was filed about, only narrower, and makes the behaviour depend on whether you happened to type inside the first half-second.

Order OCD is on. You open a unit as the first unit after a page load, so the word list is still being fetched from the core and the on-open tidy finds nothing to work with. A few hundred milliseconds later the list arrives. In this option, the block is tidied the moment the list lands, whatever has happened in the meantime — the same tidy that would have run on open, just late.

The caret never moves: uppercasing a word replaces it with a word of exactly the same length, so every position in the block still means what it meant. Nothing is scrolled, nothing is selected, focus stays where it was.
