ah-y4zb — a dialog's own sizing, and the global rule that beats it

theme.css:361 caps every modal at max-width: 95vw; max-height: 90vh. An attribute-pair selector scores 0,2,0 and a utility class scores 0,1,0, so a dialog that sets its own size is silently overruled. The markup reads correct and does nothing. It cost a full verification cycle, a P0 reopen and a second implementation session once already (ah-vwdi), and the only dialog that wins today does so with a !.

The fix makes what a component writes about itself win. The question is what to do with the sizing that has been inert all along.

Chosen 2026-08-24 — honour every sizing the markup already states
