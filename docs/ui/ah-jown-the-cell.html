Q1 — what the ITEMS cell shows for a BUY ALL

A unit may write BUY ALL GRAI instead of a number. rules/buy: “the unit will attempt to buy as many as it can afford”, and an oversubscribed line is “split among the buyers in proportion to the amount each buyer attempted to buy”.

The situation on this page. The market carries 30 grain [GRAI] at $18. Unit 5512 Hunters holds 356 SILV, 3 SWOR and orders buy all GRAI. It can afford 19 (19×18 = 342), the market has 30, so it buys 19 and is left with 14 SILV.

What the application does today — and why this is a bead. The SILVER column already works this out and shows 14. The ITEMS column does not, and shows the report’s untouched list with a + ?. The two cells on one row contradict each other.

Today — the contradiction this bead closes

Not an option. This is the shipped behaviour, here so the options below have something to be better than.

For Sale: 30 grain [GRAI] at $18
IDNAMEORDERITEMSSILVER
*5512Huntersbuy all GRAI356 SILV, 3 SWOR + ?14
  • ITEMS says the unit still holds 356 silver. SILVER says it holds 14. Both are on the same row.
  • No grain appears anywhere, though the unit will certainly have some.
  • The ledger never charges the purchase, so a later order in the same month is judged against silver that is already spent.

Option A — the settled figure, plain

The cell reads exactly as it would for buy 19 GRAI. The + ? goes, because there is no longer anything uncounted.

For Sale: 30 grain [GRAI] at $18
IDNAMEORDERITEMSSILVER
*5512Huntersbuy all GRAI14 SILV, 3 SWOR, 19 GRAI14
  • The two columns tell one story, which is the whole point of the bead.
  • A stated buy 19 GRAI already shows a settled figure with no caveat, and it rests on exactly the same unknowns (foreign buyers are invisible in both). Marking only ALL would be inconsistent.
  • Nothing new to learn: the cell means what it has always meant.
  • A figure that depends on the application’s reckoning of the unit’s income is shown as flatly as one the player typed.

Option B — the settled figure, and the mark stays

The number appears, but + ? is kept to say the figure rests on an assumption. The hover then explains it.

For Sale: 30 grain [GRAI] at $18
IDNAMEORDERITEMSSILVER
*5512Huntersbuy all GRAI14 SILV, 3 SWOR, 19 GRAI + ?14
  • Honest that an ALL is a projection rather than a quantity the player chose.
  • + ? currently means “something here could not be counted”. Reusing it for “counted, but from an estimate” gives one glyph two meanings.
  • The SILVER cell beside it carries no mark for the same order, so the row is inconsistent again — in a smaller way.

Option C — the figure marked as a ceiling

The quantity the ALL produced is written ≤19 GRAI: foreign buyers can only take it down, never up.

For Sale: 30 grain [GRAI] at $18
IDNAMEORDERITEMSSILVER
*5512Huntersbuy all GRAI14 SILV, 3 SWOR, ≤19 GRAI14
  • Says precisely the true thing: the number is an upper bound.
  • The same is true of every settled BUY in the table, so either the glyph spreads to all of them or it is arbitrary here.
  • A new glyph in the narrowest column, and formatItems currently renders <amount> <tag> and nothing else.
Recommended: A. The bead exists because ITEMS and SILVER disagree; A is the only option that leaves them saying the same thing in the same way. The uncertainty B and C want to mark is real but it is not specific to ALL — it applies identically to buy 19 GRAI, which has shown a bare settled figure since ah-agbm.
