The problem walk — saying where you are

The ‹ › buttons beside the Orders pane's title step through every problem in the turn, and F8/Shift-F8 do the same from the keyboard. A smoke test for them has failed in CI three times, on three different beads, on diffs that cannot reach it — and the fix the first two implementers agreed on is already in the file and did not hold.

Reading the code found why, and it is not a test problem. The walk's current position lives in lastDiagnostic, which is a useRef — so nothing on screen ever changes to say which stop you are on, and the test has nothing to wait for. Worse, there is a line that resets that ref to null every time validation re-runs, which is debounced and fires while you are still stepping. The walk silently jumps back to the first problem, and neither you nor the test is told.

So this bead has a player-facing side after all, and both questions below are yours.

1 · Should the walk say where it is?

The walk wraps, so there is no end to bump into — which means today there is no way at all to tell whether you have seen everything.

ANothing visible

The position becomes render state so the test can read it from an attribute, but nothing on screen changes. The smallest possible fix.

2 · What should re-validation do to a walk in progress?

You press F8 three times, then type a character. Validation is debounced, so a moment later it re-runs and the problem list is rebuilt. Today the walk silently returns to the start — the next F8 takes you to problem 1, not problem 4. This is the root cause of the CI flake, and it is also something a player feels.

R1Keep your place by identity

The walk remembers which problem it is on — the unit and the line — rather than its index. After a re-validation it finds that problem again and carries on from there. If it is gone (you fixed it), the walk resumes at the nearest one that is still there.

R2Start again, but say so

A re-validation still resets the walk — but the counter goes blank rather than lying, so the next step visibly starts from 1/6.
