A consumer's own traps — and the CLAUDE.md cerebro requires but does not ship

Two things a project using this harness must supply and currently has nowhere to put.

Traps. implement-bead and plan-bead each carry a block of hard-won facts — WebKit returning "" for clipped text, a PWA run failing after the smoke suite rebuilds the bundle, vite preview without --strictPort. In a shared submodule those are one project's scar tissue carried into every consumer's session.

A required document nobody ships. cerebro requires the consumer to have written a section called "Four Eye Principle" by that exact name — implement-bead:18,25, plan-bead:672, CLAUDE.md:127 — and offers no template for it.

One correction to the bead before deciding. It says the traps blocks "should be empty in cerebro". They should not: most of what is there is already generic and genuinely universal — a leftover preview server serving a stale bundle, -- forwarded into a test runner and read as a filter, a CI wait against a conflicted head. Only two entries are actually this project's (WebKit, and a job named native). Emptying the block would throw away knowledge every consumer needs.

1 · Who decides what goes in the consumer's traps file

The prize here is that a retrospective's "Prevent by" finally has somewhere to land — today it goes into a file nobody reads again. All 138 retrospectives in this repository have one, which is exactly why the answer cannot be "all of them".

AForge proposes, in its sweep

Forge already reads what merged and files beads for costs being paid. It gains one more output: a proposed traps entry when a retrospective's "Prevent by" names something the next agent could act on.
Forge, daily sweep
filed 2 refactoring beads
proposed 1 trap:
  "A PWA run straight after the
   smoke suite fails on timeouts
   that look like a broken worker"
  from ah-1owr.3's Prevent by
accept? (navigator)
  • The one role that already reads retrospectives for exactly this
  • Curated by something that sees the whole corpus, not one bead
  • Nothing lands without you saying so
  • Another thing Forge asks you about, on every sweep

BThe implementer appends its own

An implementer that writes a "Prevent by" naming a trap adds it to the file in the same PR. It is closest to the pain and knows whether it generalises.
implement-bead, at retrospective
If your Prevent by names something
the NEXT agent should know before
starting, add it to
.claude/cerebro-traps.md
in this PR.
reviewed with the rest of the diff
  • Written while the detail is fresh, by whoever paid for it
  • Goes through review like any other change
  • 138 retrospectives all have a "Prevent by" — most days this appends noise
  • An implementer is the worst judge of whether its own pain generalises

COnly ever by hand

The file exists and is read; nothing writes to it automatically. You add an entry when you decide something has been paid for often enough.
.claude/cerebro-traps.md
# Traps this project has paid for

- WebKit's driver answers "" for
  text it considers clipped …
- The PWA run after a smoke run …

(edited by a person, when a person
 decides it is worth it)
  • Every entry is there because somebody judged it worth an agent's attention
  • Nothing to build beyond the file and the read
  • Depends entirely on you remembering, which is what the retrospective loop was meant to fix

2 · What templates/consumer-CLAUDE.md actually says

cerebro requires a "Four Eye Principle" section by that name. A template can offer the shape and leave the policy to you, or it can offer cerebro's opinion and let you edit it down.

iThe shape, with the policy left to you

Headings, and one sentence each saying what the section must answer. No rules asserted.
## Four Eye Principle

<Say what must happen before a change
merges: who or what reviews it, what
counts as a green gate, and which
changes are exempt. The fleet reads
this section by name and will refuse
to merge without one.>

## Work tracking
<…>
  • Never puts words in your mouth about your own review policy
  • Cannot go stale — it asserts nothing
  • A blank to fill in is harder than an example to edit
  • Two consumers will answer it in shapes the fleet reads differently

iiA working default, meant to be edited

A complete, defensible policy the consumer can ship as-is or cut down — this project's, generalised.
## Four Eye Principle

Nothing merges unreviewed and nothing
merges red.

For a change built by an agent, an
automated reviewer counts as the second
pair of eyes when: one review is
requested as the PR opens; every comment
is answered; every check is green.

Everything else needs a person.
  • Works on day one, and reads as a real policy rather than a form
  • The fleet's expectations are visible instead of implied
  • A default policy is one people adopt without deciding
  • cerebro now has an opinion about review, which it can be wrong about
