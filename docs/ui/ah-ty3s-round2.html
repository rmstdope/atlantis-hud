Question 5 yours · Which editor underlines a new unit's problem

The shortfall belongs to new-1 — the core names it, and names the line buy 5 plainsmen. Under B1 that line is on screen in two editors. A finding is placed by the unit it names, not by the line it fell on (orderEditor.ts:147-150), so as things stand it would appear in one of them and not the other.

What happens today, for the record: it appears in neither. The finding names new-1, new-1 has no block, so its list is empty; and 1922's list drops it because the name does not match. That is the “partially marks” you saw.

F1 Only in the unit it names

The mark follows the name. new-1's editor underlines it; 1922's editor shows that same line clean, and counts it only in its “elsewhere” total, exactly as it counts every other unit's problems.

  • 1922's problem count means 1922's month, not its block's bytes.
  • The F8 problem walk visits each finding once, in one place.
  • A line you can see, with something wrong with it, is not underlined — and nothing on that line says to go and look at new-1.

My recommendation: F1. The counter beside 1922's editor is read as “is this unit's month all right”, and F2 makes it say no when the answer is yes. The cost of F1 — a visibly wrong line left unmarked in the creator's editor — is real, but the units table's ⚠ on the new-1 row and the Problems panel both already point at it, and under D1 both of them now open the editor that marks it.

Question 6 yours · A unit new-1 block today's bug may already have written

Arrowing onto a formed row today selects new-1 for real, the pane finds no block, and the first keystroke makes one: a literal unit new-1 block at the top level of your orders file. No check names it — nothing in the core validates that a unit block matches a unit in the report — so it exports silently and the server rejects the file.

Once this bead lands, new-1 resolves to the form 1 block instead, so any such block already sitting in a saved draft becomes text nothing on screen can reach.

G1 Leave it exactly where it is

Nothing touches the player's file. The stale block stays, unreachable, and still exports.
the saved draft, unchanged

end
unit new-1

  • The app never deletes a line the player typed.
  • Orders the player wrote silently stop being reachable, and the file they send is refused with no warning.

G2 A check names it

A new order-validation finding on the unit new-1 line: an error in the Problems panel and an underline in the export path, naming the block and saying to move its orders into the form block. Nothing is deleted; the player is told.
Problems
unit new-1 is not a unit the report shows
A unit formed this month has no number yet. Its orders belong inside the FORM 1 block that creates it. The server will refuse this block.
  • Nothing is destroyed and nothing is silent.
  • The check is general: it catches any unit block for a unit the report does not list, whatever wrote it.
  • A check in the Rust core, its message, its code and its tests — the largest of the three, and about a block the app will never write again.

G3 Fold it back into the form block on load

When a draft is loaded and a unit new-<n> block is found beside a form <n> in the same region, its lines are moved inside that block and the stale block removed. A one-time repair, invisible unless you go looking.
after loading
unit 1922
form 1
buy 5 plainsmen
end
  • The orders end up where the player meant them, and the file is valid again.
  • The app rewrites a saved file on load, with no undo and nothing said.
  • Guesswork the moment it is not one clean pair — two form 1s, none at all, or a unit new-1 in a region with no form.
My recommendation: G2. G1 sends a refused file and says nothing, which is the worst of the three whatever it costs to avoid. G3 edits a saved file without being asked and has to guess as soon as the shape is not perfect. G2 is more work than either, but it is the only one that leaves the player's text alone and tells them — and the check earns its keep beyond this bead, on any unit block naming a unit the report does not list, however it got there (a hand edit, another client, a stale paste).

If you would rather keep this bead small, say so and I will take G1 and file the check as a bead of its own at P4 — that is the honest small version. I would not take G3.
