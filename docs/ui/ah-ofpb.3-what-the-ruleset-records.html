ah-ofpb.3 — what the ruleset should record about a spell's output

This bead teaches config/public/ruleset.json what a spell creates, not only what it costs. Nothing here is visible on its own — the ITEMS cells below are ah-ofpb.5, drawn only so the two choices have a consequence you can look at. Two things came out of reading the whole data page that the bead did not anticipate, and I do not think either is mine to settle.

The bead's own list is right about the twenty-four priced spells. What follows is about nine more spells it does not mention, and about a reading of the percentages that decides what ah-ofpb.4 charges.

Q1 — the nine summoning spells say exactly the same sentence

The data page appends a normalised creation sentence to the summoning skills too, in the identical shape the artifact spells use — so the same three patterns that read ESWO read these for free. They are not priced: no via magic at a cost of, no transmutation. Today all nine have cast: null.

A1 — record only what the page prices; the summons stay silentrecommended

A creation is kept only for a skill that also states a cost or a transmutation — which is exactly the twenty-five skills that have a cast entry today. The nine summons keep cast: null and nothing about them changes, now or in ah-ofpb.5.

"WOLF": { "cast": null } // unchanged "ESWO": { "cast": { "costs": […], "creates": [{ "tag": "MSWO", "perLevel": 5 }] } }
  • The ruleset never states as a fact a number the page itself calls an average.
  • Control caps, decay and imps breaking free are all things this bead does not model — and by staying out, it never has to.
  • The committed file changes for twenty-five skills, not thirty-four. Smaller diff, smaller blast radius.
  • Unit 8805 — a wolf master casting Wolf_Lore — still has an ITEMS column that says nothing about the six wolves arriving.
  • Bringing summons in later means another bead and another scrape change.

A2 — record every creation the page states, priced or not

All thirty-four skills carry a creation. Nine gain a cast entry that costs nothing and creates something — harmless to the ledger today, and available to ah-ofpb.5 tomorrow.

IDNAMEITEMS
*8801Swordwright L35 SWOR, 15 MSWO
*8805Wolf Master L340 SILV, 6 WOLF
*8806Necromancer L38 SKEL, 40 SILV
"WOLF": { "cast": { "costs": [], "transmute": {}, "creates": [{ "tag": "WOLF", "perLevel": 2 }] } }
  • A summoner's ITEMS column becomes as useful as an enchanter's — arguably the bigger win, since a war mage summons every single month.
  • One scrape change instead of two.
  • The column would print “6 WOLF” as fact where the page says averaging — the one thing this scraper is written never to do.
  • Says nothing about the control cap, so a level-5 mage who may hold 100 wolves and one who already holds 100 look identical.
  • Unit 8806 shows 8 SKEL where 2 were already held — and 8% of them decay before the turn resolves.

Q2 — does a percentage past 100 make a second item?

ah-ofpb.5 records your reading of 2026-08-26 and asks that it be “confirmed against the rules page before building”. I have read the rules page and it is silent — the only percentage it states anywhere is the 33% chance of starving without maintenance. The per-spell sentence on the data page is the whole of the evidence, and it reads “a 90 percent times their level chance to create a runesword”, singular.

So this rests on what you know of the engine, not on anything I can check. It does not block ah-ofpb.3 — the ruleset records 90 either way — but it decides what ah-ofpb.4 charges and what ah-ofpb.5 prints, so I would rather bank it now than ask again in two beads' time.

unit 8807 ; Runesmith, create runesword 5, holds 4000 SILV cast Create_Runesword ; 90 x 5 = 450 percent

  • Consistent with the certain spells: both families are then just “a quantity per level”, and 500% is fifteen swords at level 3 exactly as 90% is two runeswords.
  • Makes a high-level artifact mage worth what the rules seem to intend — a level-5 runesmith is a factory, not a lottery ticket.
  • The page's own sentence says “a runesword”, singular, and never mentions a second.
  • If it is wrong, the app over-promises four runeswords and over-charges 2400 silver, and the SILVER column's warnings fire on units that are fine.

B2 — a percentage is one attempt, capped at one item

IDNAMESILVERITEMS
*8807Runesmith L5−6003400 SILV, 1 RUNE
*8803Artificer L3−600300 SILV, 0–1 RING
  • Literally what the sentence says: one attempt, one item, and the level only improves the odds.
  • Never over-promises: the worst it does is under-state a mage's month.
  • Level stops mattering entirely above 100% — a level-2 runesmith and a level-5 one both make exactly one runesword, which makes studying the skill past level 2 pointless.
  • Leaves the certain and chance families with genuinely different arithmetic, which every consumer then has to carry.
