What the game data can answer — proposals (bead ah-3cj4)

The scraper takes only the ten fortifications, so a Mine — one of the commonest structures in the game — is absent from the data entirely. ah-5jkt puts that data in front of the player for the first time, which is what makes the hole visible.

The bead asks the planner to establish what is actually there to scrape before promising it. I went and looked.

§1  What is actually there counted from the committed fixture, tests/fixtures/ruleset/neworigins-data.html

I got this wrong first time and the navigator corrected me. I asked the live pages and was told /data carries no standalone structure entries and no prose. Both are false. The committed fixture settles it, and it is the file the scraper actually reads.
Mine: This is a building. Units may enter this structure. This trade structure increases the amount of iron available in the region. Quarry: This is a building. Units may enter this structure. This trade structure increases the amount of stone available in the region. Road N: This is a building. Units may enter this structure. Hermits hut: This is a building. It provides defense to the first 10 men inside it. …

Every entry has the same shape, and the product is named in the prose itself. The scraper already matches the opening — ^([^.:[\]]{1,40}): This is a building\. — and then throws the entry away unless it also finds provides defense to the first N men. That one line is the whole filter.

§2  The trap the scraper warns about, and why it does not bite

parseBuildingReference's own comment says widening past fortifications would turn a Mine from “the catalogue cannot say” into “seats nobody”, and calls that a change to ah-a2k.2's magic-study warning it is expressly not making. I checked the consumer:

crates/core/src/movement/rules.rs:641 pub fn mage_capacity(&self, kind: &str) -> Option<i64> { … } crates/core/src/orders/semantics.rs:1753 ruleset.mage_capacity(&structure.kind).is_some_and(|seats| seats >= 1)
None and Some(0) are indistinguishable to the only consumer — is_some_and(seats >= 1) is false either way, so the mage is warned either way. Adding a Mine at mages: 0 therefore changes no behaviour at all. The comment's caution was sound when written; the check that came after it made the distinction moot.

A Mine will increase the amount of iron that is available to be mined in a region. The first structure built in a region will increase the maximum production of the related product by 25%.
  • The entry answers “should I build one?”, not just “what does it cost?”.
  • The prose has to be found in running rules text, by matching the thing's name. That is inexact by nature: it will sometimes miss, and sometimes pull a sentence that only mentions the word in passing.
