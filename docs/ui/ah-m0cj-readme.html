ah-m0cj — a way in for people who want to use the app

Today the README goes: title → Where your games are kept (some 60 lines on how browser storage can lose your game) → Requirements (Node, pnpm, rustup, wasm-pack) → Install (submodule, pnpm install). Every route in is a developer route.

The prose already exists. Every release's notes carry a tested “Installing” section covering all four routes, including the Gatekeeper and SmartScreen warnings — written because the macOS build is not notarized and will otherwise say it is damaged. Nothing new needs inventing; the question is where it lives and how it stays in step.

Keeps the existing shape and moves only the new section in. The data-loss warnings are read by everyone, which matters because the browser is the easiest way in and the most fragile. Costs: ~60 lines of “here is how you can lose your game” before the reader knows how to get it at all.

The hosted instance which comes first?

https://atlantis-hud.kurelid.se needs no installation and is almost certainly what most readers want. Today it is named only under Ship it, a section about how deploys work.

 Reads
1 — hosted first“Just use it. Open atlantis-hud.kurelid.se — nothing to install.” Then the downloads. Lowest friction; a reader is playing in one click. But it leads with the option whose storage is the most fragile, and Safari users are told seven days later.
2 — desktop firstDownloads first, hosted as “or try it without installing”. The desktop app keeps games as ordinary files that your backups pick up, which is the durable choice — and the unsigned-binary friction is front-loaded onto exactly the readers least likely to tolerate it.
3 — a table of all fourOne table: route, who it suits, what to do. Even-handed and scannable, and it commits to no recommendation — which for a first-time reader is itself a cost.

Keeping one copy of the words

The install prose exists in .github/workflows/release.yml (the release-notes body, :403) and would now also exist in the README. Two copies drift.

 What happens
a — copy it into the READMEBoth read well standalone; the release notes keep working for someone who arrives on the releases page. Costs: two places to fix when the Gatekeeper story changes — which it does the day someone buys an Apple membership.
b — README is the single copy, notes link to itOne source of truth. Costs: a release-notes reader has to click through to GitHub for the step that makes their download open at all.
c — copy it, and note in both that they are a pairAn HTML comment in each naming the other, so whoever edits one is told. Cheap, and it is a reminder rather than a mechanism.

Fixed either way

Links do not go stalegithub.com/rmstdope/atlantis-hud/releases/latest, never a v0.11.0 asset path.
The macOS warning is not buriedThe build is unsigned; a reader who is not told will conclude the app is broken. It goes with the macOS download, not in a footnote.
Nothing is deletedRequirements, Install, Run, Check and test, Ship it, Rulesets, agents — all stay, retitled or introduced so the audience is obvious.
