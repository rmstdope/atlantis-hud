UI tweaks — the status bar wraps, the faction view grows

Bead ah-cp8, from GitHub issue #188. Two defects: the top status bar overflows and clips when the window is narrower than its content, and the faction view's body stops at 40% of the window height, forcing a scroll long before the window is actually out of room. Every stage below is drawn at a deliberately narrow 460px window, with the header's real contents: wordmark, game, turn, faction, the status chips, then Import · Export · ⚙ on the right.

Two questions: how the bar wraps, and how tall the faction view gets.

Chosen. B, the grouped wrap: game state on the left, the Import · Export · ⚙ actions grouped on the right, dropping to a second row as one right-aligned unit when the window is too narrow. The faction view grows to the window — its body's ceiling becomes the viewport minus a small margin, and it scrolls only when genuinely out of room. The same window-clamped ceiling is applied to all four header popovers (faction, merged factions, problems, turn messages), so the header's surfaces stay consistent.

Question 1How the status bar wraps

Both drop to two rows when the window is too narrow, and stay one row when it is not. They differ in where the break happens and where the right-hand actions land.

AFree wrap

One flex-wrap on the existing row: each item flows to the next line when it runs out of room. The break lands wherever the width says — here between the problems chip and the battles chip — and the overflowed items sit left-aligned.

BGrouped wrapchosen

The bar becomes two groups — game state on the left, the Import · Export · ⚙ actions on the right. Too narrow, and the actions drop to a second row as one unit, staying right-aligned. The game-state group can still wrap internally on very narrow windows.
