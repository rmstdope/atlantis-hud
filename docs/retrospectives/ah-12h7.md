## Three of the four review rounds were spent on comments the change had made false

**What happened.** The plan named two doc comments to rewrite (`CellMenu.teach` and
`CellMenu.teachDetail` in `packages/shared/src/studyCell.ts`) and I rewrote exactly those. Two more
comments stating the same reversed rule were not in the plan and were not looked for: `rowsOf`'s doc
comment in `workspace/StudySchedule.tsx:896` ("`Teaches…` when it is offered") and the module doc at
`studyCell.ts:8` ("a `Teaches…` row when there is somebody he could teach"). The reviewer found them
one round at a time, so rounds 1, 2 and 3 were each a single comment, and round 3 also caught that my
"the block is reflowed" answer overstated what the commit had done — it had split a line in place.

**Why.** I took the plan's list of comments as the complete list. It is a list of the comments the
planner happened to see; the change made a *sentence* false, and that sentence lived in four places.
`grep -rn "when there is somebody he could teach\|when it is offered" packages/` would have found
all four in one second.

**Cost.** Three extra review rounds and three extra commits, about fifteen minutes of wall clock. No
CI cycles — every one of them was comment-only, so all four commits rode the same CI run.

**Prevent by.** When a bead reverses a stated rule, grep the codebase for the words of the old rule
before the first commit, rather than trusting the plan's enumeration of where it is written down.
`implement-bead`'s *When the plan is wrong* already says a plan can be confidently wrong about a
symbol it cites; the same holds for a plan's list of prose to update, and the grep is the cheap
check. Worth a line in the skill beside the accessible-name grep in *Traps this fleet has already
paid for*, which is the same shape of check for the same shape of miss.

**Seen before.** None found — `grep -rli "stale comment" docs/retrospectives/` matched nothing.
