## The plan listed the expectations over `RULESETS` and missed one

**What happened.** The plan named three tests that would grow when the ruleset list did
(`settingsTabs.test.ts` twice, `games.spec.ts` once) and stated that `SettingsDialog.test.tsx`
needed no edit because it reads the labels out of `RULESETS`. `tests/smoke/settings.spec.ts:443`
also reads the row out of `RULESETS` — and asserts it equals the string `"New Origins"` exactly. It
was found by `pnpm run test:smoke`, after an 11.6-minute run, not by the fast gate.
**Why.** Established: the plan enumerated the readers of `RULESETS` it found, and a whole-word grep
for `RULESETS` across `tests/` would have found this one. A spec that *derives* its expectation from
a list still hard-codes the list's current contents.
**Cost.** One full `test:smoke` run to discover, plus a targeted rerun to confirm — about 15 minutes.
**Prevent by.** When a plan grows a shipped list (`RULESETS` here, but any exported constant a UI
renders), its *Files to change* section should be built from `grep -rn "<the constant>"` over
`packages/`, `apps/` and `tests/` rather than from the readers the planner happened to open — and an
implementer should run that grep before the first increment, treating a hit the plan does not
mention as an expectation that will grow.
**Seen before.** None found.

## A new smoke walk was flaky on its first run

**What happened.** The walk added by increment 4 presses F2 to open the game data dictionary, which
exists only once the ruleset has been fetched and parsed. It failed on `[desktop-shell]` and passed
on retry: the New Age ruleset files are around 300 KiB, and a press landing before the fetch
resolves is silently ignored. The review then caught that the obvious repair — a bare `toPass()`
retry around the press — is not idempotent, because F2 *toggles*.
**Why.** Established. The plan quoted the press as a single line, and the New Origins ruleset it was
modelled on is small enough that the race never showed.
**Cost.** One flaky attempt inside a run that was happening anyway, plus one review finding — about
five minutes.
**Prevent by.** A plan asking a browser walk to press a shortcut whose availability depends on a
fetch should say so, and say the press is retried; and any retry around a *toggle* has to check the
state before acting, or it closes what it opened.
**Seen before.** None found.
