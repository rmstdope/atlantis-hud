## The full smoke suite is red on this machine before the bead is touched, so "run it green" cannot be the acceptance

**What happened.** The plan's validation said, in terms: *"Run the full smoke suite green. That is
the acceptance and there is no substitute."* Before editing anything, I ran
`pnpm exec playwright test --project=web` on untouched `main` in a fresh worktree. It gave **240
passed, 5 failed, 1 flaky** — all six in `workspace.spec.ts` (`the units pane drags at its grip…`,
`the map under a folded panel can be clicked`, `a planned route can be written into the unit's
orders`, `selecting a passenger draws the fleet's voyage`, `the faction view uses the window before
it scrolls`, `fitting the map puts every hex clear of the panes drawn over it`). After the refactor
the same run gave **237 passed, 5 failed, 4 flaky** — the same set of tests, with two of them
swapping between "failed" and "flaky" across the two runs. CI on the same commits was **fully
green**: all four smoke shards passed.

**Why.** Not established beyond "machine-local". The tests that fail are the geometry ones — panel
boxes, map fitting, window height — so a display or window-size difference on this Mac is the
obvious suspect, but I did not prove it, and proving it was not this bead's job.

**Cost.** Two full-suite runs at ~22 minutes each, and their real value was only ever "these five
are not mine". The bigger cost is not measurable in minutes: for 45 minutes I could not tell a
refactor regression from the local noise, and had to fall back on per-increment runs of the specs I
had touched plus CI as the actual verdict. That is the right answer, but the plan sent me somewhere
else first.

**Prevent by.** Two specific things, both for the navigator to decide on:

1. **`plan-bead`'s *Validation* section should not name a green full smoke run as an acceptance
   criterion.** CI is what gates the merge here, and `implement-bead` already says so — a plan that
   promises a locally-green browser suite is promising something the fleet's machines do not
   currently deliver. "Run the specs you touched; CI is the verdict" is both true and cheaper.
2. **Whether these five are genuinely local is worth one deliberate check**, because the alternative
   reading is that CI's sharding hides them. ah-5jkt.2 recorded the inverse case — `a folded panel
   shrinks to its title bar` looked flaky and was actually main being red for hours — so the fleet
   has already been bitten once by assuming a red was environmental.

**Seen before.** ah-5jkt.2 § *"`a folded panel shrinks to its title bar` was not flaky — main had
been red for hours and nobody had noticed"*, which is the same confusion from the opposite end.
ah-f9q9 § *"The walk-buttons smoke spec failed in CI and passed eleven times out of eleven
locally"*, which is this finding's mirror image. Three sightings of "the smoke suite disagrees with
itself between here and CI", none of them yet resolved.

## Removing a function left its doc comment and its constants behind, and nothing in the gate said so

**What happened.** I removed the duplicated helpers with a script that cut from `async function …`
to the closing brace. That left each helper's preceding `/** … */` block stranded above the next
`test(`, documenting nothing — and left three `const REPORT = readReport("g7f95t71")` declarations
and their imports referenced by nobody, once the shared `loadReport` supplied the report itself. All
four were caught by the Copilot review, not by me and not by any check.

`pnpm run check:fast` passed with the dead constants in place: `lint` runs `eslint src` per package
and never looks at `tests/`, and `typecheck:tooling` covers `tests/` but `tsconfig.tooling.json` does
not turn on `noUnusedLocals`, and would not catch an unused module-level `const` even if it did.

**Why.** Established. A module-level unused constant in `tests/` is outside everything the fast gate
inspects.

**Cost.** One review round and one CI cycle — about 20 minutes. Small, but it is the second time a
scripted removal across these six spec files has shipped something wrong (ah-bu2c shipped a
`ReferenceError` the same way), which is the whole reason this bead exists.

**Prevent by.** Bringing `tests/` inside a lint that reports unused module-level bindings — the
simplest form is adding `tests` to the ESLint run and enabling
`@typescript-eslint/no-unused-vars` there. That turns "the reviewer noticed" into "the gate
noticed", and it is exactly the class of mistake a blanket edit over twelve spec files produces.
Recording only; changing the gate is outside a planned bead.

**Seen before.** ah-bu2c § *"A blanket edit across six files assumed a variable name that one of
them did not have"* — same six files, same scripted-edit shape, same class of miss.
