## The plan's smoke test named a hex that is not in the base fixture

**What happened.** The plan's increment-3 test body used `1:9,53` as the second hex, saying it was
"already used as a second hex at line 825". It is — but that spec merges the ally report first, and
`1:9,53` only exists in the fixture after that merge. `SMOKE_PORT_BASE=4183 CI=1 pnpm run test:smoke`
failed with a 90s `locator.focus` timeout on `getByRole('button', { name: 'hex 1:9,53' })`, after
running the other 353 tests. `1:10,50` (swamp, Cebo, in the base turn-71 report) works.
**Why.** A hex id appearing in the suite is not evidence it exists in the walk your own test sets
up: the fixture's region set depends on which reports the test has loaded.
**Cost.** One full 10.7-minute smoke run, plus the diagnosis — about 20 minutes.
**Prevent by.** `plan-bead`, when a plan's test body names a fixture hex, region or unit, should
check it against the report the test's own `loadReport` loads —
`grep -n '^[a-z].*(x,y) in' tests/fixtures/reports/<the report>.rep` — rather than against another
spec that uses it. Naming the report alongside the id in the plan would make the check obvious to
the implementer too.
**Seen before.** None found (`grep -n "1:9,53" docs/retrospectives/*.md` is empty).

## A store action is a wider door than the plan's "the player chose this"

**What happened.** The plan put the per-hex memory write inside the store's `selectUnit`, describing
it as "the one write that knows a unit was *chosen*". It is not: two callers select on the player's
behalf — `UnitTableDock.tsx`'s `showForeignFaction` effect (first row of a foreign faction's list)
and `AppShell.tsx`'s app-load fill-in. The first stamped a *foreign* unit as a hex's remembered
unit, so returning to that hex would land on it instead of the player's own — the opposite of what
the plan intended, and it contradicted the plan's own *Decided by me* bullet. The review sub-agent
found it; the implementation and its unit tests were green.
**Why.** The plan reasoned about the *semantics* of the action ("selecting is choosing") rather than
about its *callers*. Nothing in the local tests could see the gap, because both offending callers
are effects in components `packages/shared` cannot run.
**Cost.** One extra review round and CI cycle, about 25 minutes — and a user-visible defect avoided.
**Prevent by.** `plan-bead`: when a plan hangs new state on an existing store action, it should
enumerate that action's current callers (`grep -n "selectUnit(" packages/shared/src`) and say which
of them the new state is meant for. A one-line `grep` in the plan would have caught this before the
first test was written.
**Seen before.** None found.
