# ah-728m.2.1 — retrospective

- **Implementer:** Rogue
- **Date:** 2026-09-04
- **PR:** #899

## A sibling bead shipped this one's seam while it sat handed back, and nothing said so

**What happened.** This bead was handed back on 2026-09-03 and returned to the queue by the
navigator with a specific instruction: keep PR #899, update the branch from main, fix the smoke
failure. Following that literally, `git rebase origin/main` produced 38 conflicts in one file and a
plain `git merge origin/main` produced the same 38. Reading them was the first sign of the real
cause: `ah-rzkm` (#902) had merged in the meantime and already delivered this bead's entire
structural seam — the raw/effective intent split, the resolver, and every reader routed through it —
under different names from the ones the plan specified. The branch was a large diff that duplicated
merged work and contradicted it on one rule. Resetting the branch to `origin/main` and rebuilding the
remaining gap (first-wins → last-wins, global chain grouping → consecutive segments, the wording, the
tax de-duplication) took a diff of about +240/-110 in one file, against the roughly 900-line diff
that was there.

**Why.** The bead's notes carried the navigator's triage decision and the two review rounds, but
nothing in the bead, the plan or the hand-back names the sibling that overtook it. `ah-rzkm` is not
in this bead's dependency list — the recorded blocker is `ah-728m.1` — so no `bd show` output would
have shown it either. A conflict count is the only signal, and it arrives after the worktree is made
and the first rebase is run.

**Cost.** About 25 minutes to diagnose, plus the discarded branch. Cheap only because the conflicts
were dense enough to be obviously structural; a sibling that overlapped less would have merged
cleanly into a branch that duplicated it, which is the expensive version of this.

**Prevent by.** `implement-bead`'s *A reopened bead* section tells an implementer to read
`git log origin/main --grep "(<id>):"` for what shipped under **its own** id. That does not find a
sibling shipping the same seam under another id. The cheap addition, for a bead that has been parked
or reopened, is one command before the first rebase — `git log --oneline <the branch point>..origin/main
-- <the files the plan names>` — and reading what those commits did, since a bead that sat is a bead
whose plan may have been overtaken by work with a different id. The skill's *When the plan is wrong*
already says a current-source claim is checked before its increment begins; the gap is that a parked
bead needs that check against **main's log**, not only against the current file.

**Seen before.** `docs/retrospectives/ah-cg1.md` — "A cleanly-merged rebase left two new tests
asserting behaviour the merged bead had just changed": the same shape, one bead's work invalidated by
another's merge, caught late because the merge itself was clean.

## The smoke failure the bead was handed back for was a real regression, and reproducible in 90 seconds

**What happened.** The bead was sent back for a smoke failure that had been read once as pre-existing.
It was not: `tests/smoke/persistence.spec.ts` read the caret out of `selection.anchorNode` and
asserted that node's whole text was `"@work"`. This bead moves a finding onto that line, so the editor
highlights part of it and splits the line into two text nodes — the caret had not moved at all.
Running the one spec locally (`pnpm run test:smoke tests/smoke/persistence.spec.ts`, ~90s) reproduced
it, and running it again with the change stashed proved main green.

**Why.** The assertion coupled a caret position to the DOM's node boundaries, which are a rendering
detail any change to the findings on that line can alter.

**Cost.** None on this pass — but the previous pass ended here, and the bead spent a day parked.

**Prevent by.** The stash-and-rerun comparison is what turns "is this pre-existing?" from a judgement
into a measurement, and it costs one extra run of a single spec. `implement-bead`'s *Red CI* says to
reproduce a suspected flake locally before spending a re-run; the same paragraph is the natural place
to say that a failure believed to be **pre-existing** is proved so by running the same spec with the
branch's changes stashed, since a hand-back on that belief is far more expensive than the run.

**Seen before.** None found for the caret assertion itself.
