## The plan's test vehicle could not pin the property it was written for

**What happened.** Increment 3 specified two tests built on a manufacturing PRODUCE short of its
material (`unit 2391\nWITHDRAW 5 iron\nPRODUCE sword\n`), asserting first that no
`not-enough-items` fires and then that one fires reading
`short 3 iron: this unit can have 5 and its orders spend 8`. A PRODUCE short of its material is
*capped* rather than warned about, so the scenario emits no finding at all — on `main` as well as
on the branch. `check(regions, "unit 2391\nPRODUCE sword\n")` with a five-man `WEAP 1` unit and no
iron returns `[]`. The first test therefore passed without ever having been red, and the second
could not be made to pass by any correct implementation. Same property, same phase, pinned through
a `GIVE` instead.

**Why.** The plan asserted an emitted warning for a scenario it had not run. The surrounding
evidence pointed the other way and was quoted in the plan itself: `semantics.rs:9151`'s comment
"a unit short of the iron is `not-enough-items`" is about a *region* question, and the test under
it (`a_recipe_with_inputs_is_not_a_region_question`) asserts an empty `produce_codes`, not a
shortfall.

**Cost.** About fifteen minutes: two red tests, a bisect of the fixture to find the scenario was
silent rather than the code wrong, and a replacement vehicle.

**Prevent by.** `plan-bead`'s test plan section should require that a test asserting an *exact
message* names where that message is emitted for that scenario today — a sibling test, or a run.
`implement-bead`'s *When the plan is wrong* already says a helper the plan cites for what it
decides is read before it is built on; the same care is owed to a scenario the plan cites for what
it emits, and this run is the case for saying so.

**Seen before.** None found for this shape.

## An `apt install` timeout in CI, a third time

**What happened.** The `native` job failed after 6m39s in "Install system dependencies":
`apt install attempt 2 failed or timed out` / `apt install failed twice`, stalled fetching
`libwebkit2gtk-4.1-0` (25.5 MB) from `azure.archive.ubuntu.com`. Read as infrastructure rather
than a defect, re-run once, and green in 1m39s.

**Why.** The Ubuntu archive mirror was slow or unreachable for that runner. Not this branch's
doing: no other job failed, and the same head passed on the re-run with no push.

**Cost.** One re-run and about seven minutes of wall-clock.

**Prevent by.** Nothing an implementer can do, which is why this is recorded rather than fixed:
`implement-bead`'s *Red CI* already says a wall of connection errors is infrastructure and spends a
re-run. The accumulating record is the argument for caching or pre-baking these packages in the
workflow, which is the navigator's to rank.

**Seen before.** `ah-9lv` (same apt step, `smoke`, 85 minutes), and the sightings it names —
`ah-k6i.5` (20+ minutes) and `ah-mjy` (`pwa`, 25 minutes). Fourth sighting of the same step.
