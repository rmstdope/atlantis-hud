## Two of the plan's required tests could not both exist, and one could not exist at all

**What happened.** The plan named nine increments' worth of tests. Two of them were unwritable as
specified, and both were only discoverable by reading the code:

Increment 1 asked for `an_unreadable_line_carries_its_range_kind_and_text` — parse a report whose
second region header is malformed and assert a `UnreadableKind::Region` entry. That test cannot pass
through `parse_report_full`, because `opens_a_region` (`crates/core/src/report/mod.rs:64`) decides a
block starts by calling `parse_region_header`, and `parse_region_block` rejects the block by calling
the *same* function: a header the loop notices is a header that parses, so the `None` arm the plan
asks to instrument is unreachable. The producer is still worth having defensively, so I extracted
`lost_region` and tested its cost arithmetic directly.

Increment 9 asked for a committed `.rep` fixture carrying a genuinely unreadable line, while the
test plan asked for `every_committed_report_is_read_completely` iterating
`atlantis_hud_fixtures::ALL`. The first makes the second fail. I built the damaged report in the
smoke spec instead, by replacing one unit line in turn 71.

**Why.** Established for the first: the plan quotes the `None` arm of the region loop as a producer
to fill in without noting that `opens_a_region` already gates on the same parse. Established for the
second: the fixture and the corpus assertion are in different sections of the plan (*Increments* and
*The test plan*), and nothing checks one against the other.

**Cost.** About twenty-five minutes of reading and deciding, across two increments — no CI cycles,
because both were caught before the first commit. It would have cost a great deal more had either
been noticed after the gate, and a less careful implementer would have merged an unreachable arm
with a test that passes for the wrong reason.

**Prevent by.** `plan-bead`'s plan-writing step should re-read *Increments* and *The test plan*
against each other before writing the plan, asking two specific questions of each named test: can it
actually reach the code path it is asserting on, and does any other named test forbid the fixture it
needs. Both failures here are visible from the plan text plus one grep, without running anything.

prose it required, the same shape of internal contradiction between two sections of one plan.
